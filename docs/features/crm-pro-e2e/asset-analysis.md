# CRM PRO 资产反向分析

> 采集日期：2026-08-28
> 目标应用：`APP_JAEZRUX85WI4LIR7AB4C`（宜搭CRM Pro）
> 事实来源：OpenYida CLI 结构化回读 + 宜搭管理后台只读浏览器核验
> 本文不包含 token、Cookie、成员标识或业务明细数据。

## 1. 结论摘要

CRM PRO 是一个覆盖“营销获客 → 线索分配与跟进 → 客户/联系人 → 商机阶段推进 → 产品报价审批 → 合同 → 回款/开票 → 售后 → 经营分析”的完整销售 CRM。资源总图如下：

| 资产类别 | 数量 | 主要用途 |
| --- | ---: | --- |
| Portal 门户 | 1 | 应用首页壳、公告、待办与快捷入口 |
| Display 自定义页面 | 8 | 首页、公共池、我的线索/客户/商机/计划、联系人工作台 |
| Manage 数据管理页 | 11 | 表单数据管理与流程数据管理 |
| Receipt 普通表单 | 16 | 业务主数据和交易数据 |
| Process 流程表单 | 1 | 产品报价审批 |
| Report 原生报表 | 19 | 营销、销售、回款、售后和首页指标 |
| 集成自动化 | 18 | 11 表单事件 + 1 定时 + 6 手动/卡片触发 |
| 聚合表 | 0 | 当前应用未配置 |

应用当前已启用；主题为蓝色，详情页采用上下结构，流程采用聚合模式；默认语言为简体中文，同时启用 English。应用访问控制关闭、允许外部联系人通讯录，应用管理员只配置了主管理员角色。首页自定义页已开启公开访问。

## 4. 核心业务状态与关系

```text
营销活动
  └─产生→ 线索池（未分配 / 未转换 / 已转换）
       ├─领取/分配/转交→ 负责人
       ├─跟进→ 跟进记录 / 跟进计划
       └─转换→ 客户 + 联系人
                    └─创建→ 商机
                         ├─阶段：需求发现→需求确认→方案报价→商务谈判→赢单/输单/无效
                         ├─关联→ 产品明细
                         └─报价审批→ 产品报价
                                      └─生成→ 合同订单
                                               ├─回款计划→回款单
                                               ├─开票申请→财务信息
                                               ├─退货处理
                                               └─服务工单
```

## 5. 权限模型

### 5.1 应用级

- 应用访问控制：关闭。
- 外部联系人通讯录：允许。
- 管理员：只配置主管理员；未配置数据管理员和开发管理员。
- 首页公开访问：开启；组织内分享地址未配置。

### 5.2 表单级

- 多数普通表单有两个权限组：
  - 全部成员：可查看/管理本人提交的数据，常见操作为查看、编辑、打印、删除、历史、评论。
  - 平台/应用管理员：全量数据和全部操作。
- 线索池、客户的默认权限组名称写“查看本人提交数据”，但实际数据规则回读为 `ALL`，名称与规则不一致。
- 线索池、客户、联系人使用 `CUSTOM` 字段范围，适合验证字段级权限回读。
- 产品报价普通成员可提交并查看本人流程数据，支持查看、打印、历史、评论，不具备编辑/删除；管理员为全量权限。

E2E 不应只断言权限组名称，应同时断言成员范围、数据范围、操作范围和字段范围。

平台导航保留，顶层顺序为：门户/首页、市场营销管理、客户管理、合同回款管理、产品管理、业务报表、产品售后服务、基础业务数据、系统配置。

## 8. 已观察到的质量风险

| 编号 | 现象 | 类型 | E2E 断言 |
| --- | --- | --- | --- |
| Q1 | 首页多张图片在浏览器可访问性树中显示 `Image 404` | 素材/发布 | 页面不得出现破图；核心入口仍可点击 |
| Q2 | 客户和联系人“性别/关键决策人”选项仍是“选项一/二/三” | Schema 内容 | 多轮编辑替换为真实业务选项 |
| Q3 | 客户表有两个同名“客户状态”字段 | 字段语义 | 字段名唯一且状态维度清楚 |
| Q4 | 权限组名称“本人数据”与数据规则 `ALL` 不一致 | 权限 | 同时校验名称与实际规则 |
| Q5 | `商机推进`、`销售简报`显示已开启但更新未发布 | 自动化版本 | 发布态、启用态和最新定义一致 |
| Q6 | 手动触发描述出现 `null` | 管理 UI/Schema | 触发描述无空值泄漏 |
| Q7 | `订单提交分析`引用非本应用 cube，首页日历无数据 | 报表绑定 | 所有报表数据源属于目标应用或显式外部依赖 |
| Q8 | CLI 同一 token session 下部分端点曾短暂 401，重试成功 | CLI 稳定性 | 预检成功后只读端点应稳定；失败要可重试并明确归因 |
| Q9 | 中英文资源标题存在复制/未命名痕迹 | i18n | 中英标题和关键选项完整、无模板占位 |
| Q10 | 产品报价由发起人本人审批 | 流程治理 | 后续编辑改成独立审批角色并验证权限 |

## 9. 对 OpenYida 能力覆盖的意义

该应用可验证 `yida-app` 编排，以及 create-app、create-form-page、get-schema、data-management、form-permission、create-process/process-rule、integration、report、canvas/custom-page、publish-page、page-config、nav-group、app-permission、i18n、app-lifecycle 等能力。当前样本不包含聚合表、HTTP 连接器和业务关联规则的独立配置，因此这三类不能从现有资产声称已覆盖；可作为扩展轮次另行加入，但不应伪装成原应用事实。
