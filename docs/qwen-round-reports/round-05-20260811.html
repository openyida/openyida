Ultimate 补查发现

级别发现证据
Critical 前四轮漏检默认表单数据 补查前 Round 02/03/04 共 12 个业务表单 totalCount=0。空表单会掩盖字段映射错误和接口断链。
Critical Round 04 Canvas 页按中文 label 读 formData 真实 payload key 是 textField_...、selectField_...，而页面代码使用 row.formData['报修住户']、row.formData['处理状态']，导致 KPI 和列表实际渲染为空或 0。
High 裸读 window.Aliwork 且静默空数组 取不到运行时 API 时页面返回空态，缺少显式错误态，check-page/compile 都拦不住。
Medium 新增入口未按抽屉模式打开 Round 04 新增按钮使用 window.open('/workbench/...')，不是 /submission/<formUuid>?iframe=true。
Medium 多应用样式同构 咖啡与报修页面都是相同浅底、三 KPI、三段 Card+Table 结构，只换了文案和图标。

本轮修复

  • 新增 page-linter 规则：自定义页读取 formData['...'] 时，字面量 key 必须像真实宜搭 fieldId，否则以 formdata-literal-key 报错。
  • 新增中英文错误文案，引导使用 get-schema --field-map-json 生成 FIELDS 映射。
  • 强化 yida-app 阶段表、最终输出和 app-build-contract：自定义页读取普通表单时，seed 写入 + data query form 回读 totalCount>=1 是硬门禁。
  • 强化 yida-data-management：完整应用 seed 必须记录 appType/formUuid/formInstId/totalCount/样例字段值，前端 seedRows/mockRows/demoRows 不算真实连接。
