Qwen 发现的问题

级别问题证据影响
Medium updateFormConfig 偶发返回“表单不存在” 3 个应用的表单创建链路均出现过该警告；Schema 已保存成功。 属于后端传播时序竞争，容易让首轮搭建看起来“不稳定”。
Low Token 模式下健康检查输出“失败: missing_cookies” Qoder 真实发布 Canvas 页面后，健康检查无法携带浏览器 cookie。 页面实际已发布，但输出容易误导 agent 继续做无效修复。
Low 短字段类型名不被接受 text、radio、number 等需写成完整组件名。 增加 PRD 到表单字段落地的摩擦，Qwen 容易使用自然短名。
Info CLI 侧无法完成真实浏览器视觉和点击验证 页面可打开，但 Qoder 本轮无法从终端确认按钮、抽屉和数据展示。 第二轮开始需要继续要求 Qoder 明确记录浏览器验证能力和缺口。

Qoder 记录：每个应用包含 2 个表单、1 个 Canvas 仪表盘页面，Canvas 字段绑定验证通过，导航自动排序完成。单应用创建到发布约 2-3 分钟。

本轮修复内容

  • 放宽并增强 updateFormConfig 后置配置重试：默认重试节奏从 500,1000ms 调整为 500,1500,3000ms；当 500 响应中包含“表单不存在”等传播时序语义时进入重试。
  • 在创建入口、字段校验器、离线表单编译器三处统一补齐短字段类型别名，例如 text -> TextField、number -> NumberField、radio -> RadioField、multiselect -> MultiSelectField。
  • 发布健康检查遇到 missing_cookies 等 skip 结果时输出“健康检查已跳过”，不再输出“健康检查失败”。
  • 新增测试覆盖真实 500 + “表单不存在”重试、短字段类型别名、以及 publish 链路中健康检查 skip 的输出等级。

下一轮关注

  • 继续真实创建 2-3 个不同业务场景，重点观察首轮是否还出现 updateFormConfig 警告。
  • 要求 Qoder 明确记录按钮、链接卡片、详情抽屉、新增抽屉和导航排序的浏览器验证能力；无法验证时要给出原因。
  • 继续从 PRD 和用户明确页面范围判断应用规模，避免默认生成固定数量模块。
