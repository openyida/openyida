OpenYida 2026.8.11 到 2026.8.14 改造对比报告

8.14 的核心不是继续堆能力，而是把 8.11 以来快速增长的技能说明重新收拢成“短入口 + 阶段化 workflow + 按需参考文档”。结果是 npm 包体积略降、核心 agent 首读入口显著变短，同时保留了更细的完整应用搭建流程和发布证据约束。

一句话判断：8.14 是一次面向 agent 执行质量的结构性整理。它牺牲了少量文件数量简洁度，换来入口降噪、阶段边界更清晰、完整应用搭建链路更稳定，以及 npm 包整体小幅瘦身。

主题 8.11 状态 8.14 改造 影响

发布证据 发布目标、真实发布证据、final 输出口径在多个位置重复出现。 优化 yida-publish-page 和 yida-app Step 8/9，强调真实发布、主入口链接和业务语言总结。 减少“本地编译等同发布”“输出一堆 ID 而不是业务结果”的误判。
帮助与能力入口 README/能力列表链接还在旧分散入口。 帮助网站统一到 demo.aliwork.com/o/openyida/helpCenter，补齐 capabilities、CLI Reference、Examples、Changelog 链接。 用户文档入口更集中，README 承担引导而不是复制完整能力清单。
agent 能力识别 agent 能力摘要对运行时 auth 快路径覆盖不足。 增强 lib/core/agent-capabilities.js 并新增 tests/agent-capabilities.test.js。 更准确识别当前环境的登录态/能力，降低 agent 错误引导登录或跳过 auth 检查的概率。
