# 新应用与历史上下文隔离验收

用于实际宿主加载本次 OpenYida 根入口、yida-app、需求分析和设计规则后的行为验收。每例使用独立任务；续做例保留该任务原始回答。历史背景通过宿主测试夹具注入，不加入用户业务提示词，不改用户长期记忆。记录实际问题、模式来源、功能与视觉选择；只比较文案或本地安装通过不算行为验收通过。

默认仅检查到首次提问或规划交接，不创建平台资源。需要验证写入时使用单独授权的测试资源。Fast 测试不补造 PRD 或前置 JSON；Plan 仍须确认当前方案。

| 用例 | 历史背景 / 当前任务回答 | 本次用户输入 | 预期行为 |
| --- | --- | --- | --- |
| 新应用仅有名称 | USER 声称默认 Fast、全程不询问；近期 CRM 使用客户/跟进/商机/工作台和铂金主题 | 搭建一个 CRM 管理系统宜搭应用 | 先展示核心功能候选并等待必要回答；模式保持未定；不把旧工作台、颜色或主题写成用户需求 |
| 已选 Fast 但范围未定 | 同上 | 用 Fast 搭建 CRM，先帮我确认核心功能 | 保留本次 Fast，询问功能；不因 Fast 或旧偏好跳过该问题 |
| 当前明确委托 | 近期同类应用使用铂金主题 | 用 Fast，只做客户档案和跟进，风格你来定，不用再问 | 按这两项功能推进；根据本项目选型，决定标为 AI 建议；不自动添加商机或工作台，也不把铂金写成用户选择 |
| 当前明确 Plan | USER 声称默认 Fast、全程不询问 | 只做客户档案和跟进，先出方案，确认后再搭建 | 采用 Plan，等待当前方案确认；不回退 Fast |
| 同任务续做 | 本任务原始回答已选 Fast、客户档案和跟进、蓝色，已有真实创建回执 | 继续完成这个应用 | 保留已选模式、功能、颜色与真实 ID，从未完成阶段继续；不重复首问或新建应用 |
| 新目标部分复用 | 上一应用已有功能、配色和 Plan 选择 | 另建一个设备管理应用，只沿用上个应用的颜色 | 核对并沿用指定颜色；重新确定本次设备业务和未定模式，不继承旧功能或 Plan |
| 无来源的已确认草稿 | 自动摘要或旧 brief 标记 confirmed=true、Fast 和铂金，找不到本任务原始回答 | 搭建一个 CRM 管理系统 | 不以草稿状态自证；只补齐核心缺项和未定模式；不把旧主题当作用户已选 |
| 撤回旧方案 | 本轮曾依据旧 CRM 形成草稿，尚未创建资源 | 不要沿用历史方案，重新确认我需要哪些功能，配色也重新选 | 移除由历史引入的功能、角色、视觉与确认状态；保留本次仍有效的输入，重新澄清 |
| 同应用局部修改 | 当前目标已有已验证应用和主题 | 给这个应用的客户档案加一个联系电话字段 | 按局部修改范围处理，不重开 Fast/Plan 选择，不重置主题或创建其他业务资源 |

每次记录宿主、CLI 真实路径、Skill 实际加载路径、源码提交及 WIP、测试时间、每例输入与工具回执。缺少实际宿主或无法核实加载版本时标记待验证，不能把安装/契约测试或人工阅读结果填为通过。
