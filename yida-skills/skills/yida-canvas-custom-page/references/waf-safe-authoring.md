# WAF 安全误拦规避写法

> **仅在用户反馈发布反复失败、且疑似被平台安全（WAF）拦截时才启用本文档。**
> 只用于已确认的 WAF 误拦排查；正常生成 Canvas 页面不套用这些规则。

## 何时判定为 WAF 拦截

发布返回 **HTTP 200，但响应体不是 JSON**，且 body 中含 `waf_block` 字样，即为安全拦截（并非业务报错）。表现为「发布一直失败」但登录态、参数、源码语法都正常。

## 定位命中片段

在用户授权的测试页面保留完整源码副本，用二分法定位被拦截的源码片段；不得在交付页面发布删减内容。未获得测试目标时保留错误证据并停止：

1. 注释/删除页面源码的一半，重发 `openyida publish`。
2. 若仍被拦截，命中片段在保留的一半；若通过，命中片段在删掉的一半。
3. 继续对半缩小范围，直到定位到触发拦截的具体写法。
4. 按下方规则替换该写法后，恢复其余代码并重新发布。

## 规避写法

### 1. 不写正则字面量

日期/字符串解析改用非正则方式：`String.split()`、`slice()`、`Number()`、`Date` 等。

确需正则时用 `new RegExp('...')` 动态构造，避免形如 `\d{4}` 这类字面量直接出现在源码里。

- 命中示例（避免）：直接在源码里写 `/\d{4}-\d{2}-\d{2}/` 之类的正则字面量。
- 安全写法：`new RegExp('\\d{4}')`，或直接用 `str.split('-')` 取段、`Number(x)`、`new Date(str)` 解析。

### 2. 不出现危险 HTML / 脚本字符串字面量

源码中避免出现下列字符串字面量：`<script`、``eval(` ``、`innerHTML`、`javascript:`、`onerror=`、`<iframe` 等。

事件处理写成 JSX 的 `onClick={fn}`，不要拼成 HTML 属性字符串（如把 `onclick="..."` 拼进字符串再注入）。

### 3. 不出现注入特征串

源码中不要出现 `union select`、`or 1=1`、`../`、`$(...)`、`/etc/passwd` 等注入特征串，即使只是常量、注释或示例数据。

## 复发时的处理顺序

1. 确认是 WAF 拦截（HTTP 200 + 非 JSON + `waf_block`），排除登录态/参数/语法问题。
2. 二分法定位命中片段。
3. 按上述规则替换写法。
4. 恢复完整源码，重新发布并回读验收。
