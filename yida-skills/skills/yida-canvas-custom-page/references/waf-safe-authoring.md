# 发布异常：先核实证据

按本次原始回执定位失败阶段，不预设 WAF。

## 正常事件写法

React/JSX 的 `onClick={handleClick}`、`onClick={() => handleClick()}` 和 `onChange={handleChange}` 都是正常事件绑定。源码含 `onClick=` 不是 WAF 证据；它与 HTML 字符串中的内联事件属性不同。

保留正常事件绑定；不因发布失败改成属性展开、计算属性或编码，更不声称能“绕过 WAF”。仅修复已定位的源码或接口问题。

## 证据与处理

| 本次可见证据 | 可得结论与下一步 |
| --- | --- |
| 本地编译或发布前校验报错 | 按具体源码位置修复，不改写为网关故障 |
| CLI 明确返回认证、组织、权限、目标或参数错误 | 按对应错误恢复，保留原应用和页面 |
| 超时、HTTP 非 JSON、403 或空响应 | 原因未确认。先只读核对是否保存成功，保留错误；这些现象不能单独确定 WAF |
| 原始响应明确包含 `waf_block` 或平台明确返回安全拦截码 | 仅记录拦截提示及时间、接口、状态、可用请求 ID，交由平台核对规则；不能推断命中 onClick |
| 平台规则日志或授权测试的稳定对照明确指向具体内容 | 按日志解释命中原因；正常 JSX 误拦由平台修复，不混淆绕过 |
| 发布回读通过但页面空白/交互报错 | 检查运行时异常、依赖、导出及数据状态，不归为发布拦截；页面检查按本地验收规则执行 |

HTTP 工具可能只返回 `__httpStatus`、`__nonJsonResponse` 和错误摘要。缺少原始响应或日志时保持未知，不编造 body、请求 ID 或拦截原因。

结果未知先读回，不盲目重发或向交付页面发布删减源码。复现须有授权的独立测试目标，每次只改一个因素、保留对照；一次换写法成功不证明因果。

## 对用户的表达

普通任务说明业务影响，如“页面暂未发布成功，正在核对保存结果”。用户问原因时按证据说明；不足则说“发布返回异常，具体原因尚未确认”。不把推测当事实，不输出“onClick 被判风险”“改属性展开绕过”等无证据结论。
