# 发布异常：先核实证据

按本次 CLI 回执区分编译、业务保存与页面运行错误，修复已定位的问题。

## 正常事件写法

保留 React/JSX 的 `onClick={handleClick}`、`onClick={() => handleClick()}` 和 `onChange={handleChange}`。事件属性本身不是拦截证据，属性展开或编码不作为排障方案；正常 JSX 误拦交由平台修正规则或发布通道。

## 证据与处理

| 本次回执 | 下一步 |
| --- | --- |
| 超时、HTTP 非 JSON、403 或空响应 | 记录原因未确认，先只读核对保存结果 |
| 明确的 `waf_block` 或安全拦截码 | 保留提示、时间、接口、状态和可用请求 ID，由平台核对规则；具体命中内容须有日志或稳定对照支持 |
| 平台日志或授权测试明确定位问题 | 按已确认的因果解释和修复；一次换写法成功只记录为对照结果 |
| 发布回读通过，页面显示或交互异常 | 检查运行时异常、依赖、导出和数据状态；页面检查遵循本地验收规则 |

HTTP 工具可能只返回 `__httpStatus`、`__nonJsonResponse` 和摘要。保留实际拿到的证据，其余信息记未知。结果未知先读回；确需复现时使用授权的独立测试目标，每次只改一个因素并保留完整源码和对照。

## 对用户的表达

按[完成总结](../../../references/user-facing-summary.md)说明业务影响与必要操作。用户问原因且证据不足时，可说“发布返回异常，具体原因尚未确认”；已定位时说明实际原因及处理结果。
