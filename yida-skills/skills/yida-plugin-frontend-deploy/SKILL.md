# 宜搭插件前端资源部署

本技能负责从插件源码到稳定资源地址，再到真实宿主加载的交付，不代替平台插件生命周期管理。

## 范围与交接

- 插件构建、资源托管、`remoteEntry.js`、chunks、容器名或加载失败：使用本技能。
- 创建插件/版本、保存开发配置、安装启停、权限申请及官方编辑器发布：通过 `use_skill("yida-plugin-lifecycle", "管理插件生命周期")` 加载对应技能。
- 仅咨询或准备本地配置无需宜搭登录；调用平台 API 前核对登录账号与目标组织。没有插件开发权限时，通过 `use_skill("yida-plugin-lifecycle", "引导申请插件开发权限")` 进入申请流程，资源托管权限单独处理。
- 用户明确禁止或暂缓某渠道时排除该渠道；只要求引导、暂不测试时不执行构建、探测、流水线或部署。方案选择不授权自动创建仓库、上传源码、购买云资源或发布到组织。

## 执行顺序

1. 确认已有插件 ID/版本、目标宿主/扩展点、源码项目及本次执行范围；缺少插件或版本时交回生命周期技能，不凭展示名编造 ID。
2. 核实集团/非集团开发环境、企业静态资源服务器、HTTPS 域名及发布权限。身份以用户说明与已核实权限为准，不能只凭宜搭域名、内网可达或本地仓库推断。
3. 读取[创建与部署引导](./references/frontend-hosting.md)，复用现有企业渠道；没有现成渠道时国内推荐码云 + 阿里云 OSS，GitHub Actions + Pages 作为备选。逐步给出入口、填写项和完成后需要提供的信息。
4. 读取[前端构建与加载契约](./references/frontend-contract.md)，检查真实项目的 Module Federation 配置、容器名、扩展点导出、publicPath 和依赖。获准执行后才安装依赖、构建、上传完整产物；仅编译成功不能宣称宿主可加载。
5. 获得真实稳定 HTTPS 入口后，通过 `use_skill("yida-plugin-lifecycle", "保存插件开发版本配置")` 交接，基于版本回读保留三段配置、摘要和备份，再保存核对；资源部署不自动发布到组织。
6. 用户授权验收后，通过 `use_skill("yida-plugin-lifecycle", "核对插件可用性的四层证据")` 分别记录持久化、资源可达、注册候选和真实消费。加载失败按契约排查；没有执行的层级明确标为未验证。

## 边界与完成标准

- 开发者身份不等于 SDK 的“官方插件”分类，第三方资产目录不固定为 `yida-components`；完整 URL、容器名与当前宿主规则分别核实，不能只看输入框前缀。
- 登录、协议、费用、公开访问由用户确认；需要用户操作时打开对应官方页面，不索要聊天中的密钥，不将内部代码或凭据上传外部仓库。
- 接入要求不明确时，向宜搭插件接入负责人或已有开发者确认外部 URL 支持、域名、版本和上架约定；不要求非集团开发者取得内网发布权限，不承诺任意 URL 都能加载。
- 方案交付需列明渠道、所需账号/权限、实际入口或缺失项，以及已做/未做步骤。部署交付需记录真实版本目录、完整产物及资源地址；运行成功只以当前宿主的消费者执行证据为准。
