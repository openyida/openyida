# 预审与运行

## 选择操作通道

宜搭流程查询与数据操作加载 [yida-data-management](../../yida-data-management/SKILL.md)。数字员工任务操作按当前 DWS 官方技能和目标组织实际能力执行；先用员工身份验证待办、原流程详情与节点动作，不能根据同名 OA 命令推定所有宜搭来源都受支持。

OpenYida 的 `data execute task` 使用当前宜搭调用身份；只有它与获授权的实际处理人一致且平台接受该任务时才能使用，不能把管理员登录态当作数字员工身份。DWS 或其他已验证通道不能处理目标宜搭任务时，保留建议或转人工，说明该来源的执行链路尚未打通。

以下是 OpenYida 只读定位的命令形状，所有尖括号值来自本次真实回执：

```bash
openyida get-schema <来源应用标识> <流程表单标识> --field-map-json
openyida data get process <来源应用标识> --process-inst-id <源流程实例>
openyida data query process-tasks <来源应用标识> --process-inst-id <源流程实例> --json
openyida data query operation-records <来源应用标识> --process-inst-id <源流程实例>
```

Schema 读取遵守其管理权限；普通成员的流程只读查询不以管理员接口成功为前置。表单类型与字段信息在配置阶段由有权身份核验。

## 单笔处理

1. **定位**：核对来源应用、流程表单、实例和当前任务，确认仍可处理、处理人是目标员工且属于授权预审节点。明确区分新流程版本和已有实例。
2. **读取**：读取当前材料与生效规则，保留版本。缺少必备材料时生成具体补件项；条件冲突、附件无法读取或缺少规则时保留草稿并交人工判断。
3. **预审**：先产生意见草稿。材料齐全且满足已确认规则时，执行该节点允许的预审动作；缺件时按授权提交评论或补件动作。评论不自动等于退回或审批完成。
4. **回读**：动作后读取源流程当前状态、操作记录和意见，确认实际结果。超时或返回不明时先核对是否已执行，不立即重发。
5. **同步**：按受理键更新台账，追加跟进历史；草稿、已写入意见、实际节点动作和源流程结果分别存储。源动作成功但同步失败时，只补数据同步。
6. **通知**：仅按已确认的对象、内容和时机通知；保留投递结果。未授权发送时交付建议内容，不实际发送。

完成预审后，源流程可能仍在人工终审。台账冲突以源流程为准，并记录同步缺口。已处理任务、相同材料重复投递或并发触发按[去重与数据规则](data-and-privacy.md)恢复，不重复审批或评论。

## 持续运行

先手动跑通一笔，再接入用户选择的执行环境。

- **消息触发**：DWS 管理员工连接与触发范围，核验真实消息接收、执行和回复。OpenYida 不提供通用钉钉事件订阅、Stream 或 HTTP 回调接入；不生成连接器来冒充该能力。
- **定时运行**：确认用途、频率、时间及时区、处理范围、节假日和通知对象。使用宿主已支持的调度入口，验证实际触发日志、身份与回写；没有可用调度环境时明确交付手动运行方式。
- **恢复**：先读连接/调度状态和上次任务进度，重用已有员工与业务资源。电脑休眠、进程退出、登录失效或绑定受阻时说明实际影响，不宣称全天在线。

## 验收

在已授权测试目标验证齐件预审、缺件评论、补件复审、人工终审及源状态同步；跨应用逐来源核验。同一事件重复投递、动作超时、台账写入失败、已完成任务及权限不足均需保留正确恢复路径。

验收记录绑定本次环境、流程版本、员工身份及真实实例/任务；分别报告任务投递、材料分析、源动作、台账同步、通知和自动触发。历史试点结果、发布回执和配置保存不能代替这条链路的运行证据。
