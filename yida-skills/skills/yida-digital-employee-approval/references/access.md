# 工具与身份

## 准备工具

OpenYida 管宜搭应用、流程、数据、视图和页面；DWS 管钉钉数字员工及其支持的身份和连接。DWS 独立安装、登录和升级，OpenYida 不自动安装或内置它。

- OpenYida 按根技能执行 `openyida agent-capabilities --summary-json`，需要恢复认证时加载 [yida-login](../../yida-login/SKILL.md)。使用本次宿主提供的组织上下文，不从旧案例带入账号。
- DWS 安装与认证使用 [官方说明](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)。先检查 `dws version`；加载该版本提供的 `dingtalk-tag` 数字员工技能及其共享执行契约。宿主不能加载外部技能时，按官方文档和对应命令的窄 Schema/帮助核对能力，不猜参数。
- 只读取需要的 profile 摘要，确认组织与账号；多候选无法从本次上下文消歧时询问用户。记录 profile 引用，不输出认证票据。

## 核对身份和权限

| 身份 | 核对内容 |
| --- | --- |
| 宜搭调用者 | 当前环境和组织、来源应用可见性、所需表单与流程操作权限 |
| 数字员工管理者 | 目标组织是否开通能力，以及该账号实际的创建、编辑和发布权 |
| 数字员工执行者 | 已发布员工的真实身份、目标组织归属、实际分配的节点任务与可执行动作 |
| 应用级访问身份 | 仅当接口需要时核验企业内部应用及其读写权限、授权范围和可用数据通道 |

列表可查不代表有创建权；组织可见不代表所有人都能触发；管理员能读流程不代表员工可以处理。测试申请人、预审员工和终审人分别使用其真实权限。

## 数字员工与运行方式

1. 复用已有员工时读回真实 `agentUuid`、组织、主程序类型、发布配置和能力资源。创建时按 DWS 实际契约确认名称、职责、`open_code` / `local_agent` 类型和响应方式；不把本地接入默认套到所有员工。
2. 创建或连续写操作按 DWS 当前确认规则汇总预览，沿用用户对同一具体范围的确认。草稿创建成功后保留员工标识；保存或发布失败从该员工恢复，不再 create。
3. 只需员工身份时，使用 DWS 支持的 `manage login`；需要接入本地 Agent 时，使用支持的 `connect`。身份登录与建立连接分别处理；连接不代替创建、修改或发布。
4. 本地接入先核对该版本支持的宿主、绑定状态和触发范围；以 `connect status` 等实际结果核验。白名单人员在员工身份下精确解析，不将组织可见性当作触发授权。
5. 本机、云端和托管宿主各自验证 CLI、技能、凭证引用与持续运行条件。宿主不支持本地连接时，保留已完成资源并说明缺少的运行能力，不生成自建轮询后台作为隐式替代。

## 宜搭数据通道

同一身份可通过 OpenYida 完成目标数据操作时优先复用。需要应用级访问时，使用 [yida-dingtalk-openapi](../../yida-dingtalk-openapi/SKILL.md) 和 [yida-connector](../../yida-connector/SKILL.md) 按最小权限配置；先用只读请求确认返回目标应用的数据，再验证授权内写入。

`systemToken` 属于目标宜搭应用。支持的连接器测试或集成自动化使用 OpenYida 内部解析或服务端绑定，不把它写入前端、动作默认值、技能文件或对话。应用密钥由用户在官方后台或受控凭据存储配置；不索取明文。

权限受阻时使用真实回执中的申请入口；无直达入口时指引目标组织管理员核对对应权限。登录失效、组织未开通、创建权不足、数据权限和字段映射错误分别处理，保留已有资源与非敏感回执。
