# 工作台与原生详情

用户需要跟进页面时，以已确认范围配置总览、受理列表、来源与规则、跟进历史。总览使用 Canvas；管理列表优先复用原生数据视图，保留其搜索、筛选、分页与权限。布局、主题和导航交给完整应用的设计输入，不从旧案例继承固定色彩或图表。

## 统计与列表

数据模型见[台账模型](data-and-privacy.md#台账模型)。总数、分布和趋势使用同一受理范围，区分助理状态与源流程状态；查询完整分页或使用明确范围的聚合。权限不足、分页上限或部分读取失败时显示范围与缺口，不将首屏数量当累计总数。业务时区、零值和空状态按真实数据处理。

通过 [yida-form-view](../../yida-form-view/SKILL.md) 读取真实视图和 `configHash`，针对性保存所需列、顺序、筛选与按钮并回读。意见、当前节点和两个状态应可辨识，保留用户已有显式配置。

## 打开原申请

受理台账可以是普通表单。它的系统详情展示台账；源流程意见、节点与走向图应打开对应申请的宜搭原生流程详情。

1. 每行保存来源应用、源流程表单和源流程实例，结合只读查询核对申请标题。多个来源使用明确的应用/表单组合允许列表；缺失或未知组合时提示关联不可用，不猜首个来源。
2. 按 [yida-canvas-custom-page](../../yida-canvas-custom-page/SKILL.md) 的表单打开容器示例构造原生流程入口。使用真实源实例，保持平台鉴权；不得用台账实例替代源流程实例，或接受任意外部 URL 跳转。
3. 需要同页侧滑时，用 [yida-custom-button](../../yida-custom-button/SKILL.md) 核对当前版本的 `linkToPage`、`openWith: slide` 和行参数映射能力。接收页在本次部署的来源允许列表内构造详情，先发布并验证接收页，再配置原生行按钮。
4. 按需传递 `approvalSourceApp`、`approvalSourceForm`、`approvalSourceInstance` 和固定 `approvalDisplay=panel`。来源与实例来自当前行，表单来自该行或已经核实的唯一映射；URL 参数编码，服务端权限仍由平台校验。
5. 更新已有按钮和视图时先读取当前配置，按对应技能的 hash 校验保存与回读。在用户要求一个“详情”入口时，确认新入口可用后再调整重复入口，保留其余操作。

当前平台不支持侧滑或参数传递时，提供已验证的独立原生详情入口，说明打开方式。不要将新开标签后再弹抽屉描述为同页侧滑。

## 页面验收

发布使用 [yida-publish-page](../../yida-publish-page/SKILL.md)，修改已有页面先执行 [发布防覆盖检查](../../yida-openyida-publish-guard/SKILL.md)。配置回读与浏览器验收分别记录。

在具备实际浏览器能力的授权测试环境中，从每个已接入来源打开样本，核对申请标题、源实例、当前节点、真实意见及原生流程走向图；关闭后列表位置与操作仍正常。另测缺失关联和无查看权限的样本，保留平台反馈，不打开其他申请。未完成浏览器测试时明确说明。
