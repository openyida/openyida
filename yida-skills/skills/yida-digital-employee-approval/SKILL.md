# 宜搭与数字员工审批

让钉钉数字员工处理明确分配给它的宜搭预审任务，材料齐全后交人工终审；工作台按需汇总已受理申请，并能打开原申请的原生流程详情。

## 选择本轮范围

- **新建完整应用**：通过 `use_skill("yida-app")` 交给应用技能编排，按该技能选择 Fast / Plan。本技能补充数字员工、预审规则和验收要求，不另起应用搭建流程。已由 `yida-app` 调度时沿用当前模式和阶段，不再次进入入口或重复首问。
- **接入已有流程**：核对用户指定的流程和数字员工，保留现有字段、权限、历史及页面；只实施已授权的接入范围。
- **运行或排障**：先读当前实例、任务、员工身份和执行回执，从未完成步骤恢复，不重复建资源或执行节点。

这里只处理钉钉数字员工；宜搭内置应用级/空间级 AI 助理、流程代理、普通群机器人和虚拟人形象是不同资源。用户仅说“数字人”且上下文不明时，先确认所指产品与任务。

## 开始前

1. 沿用本次对话已确认的来源应用、申请类型、必备材料、预审通过条件、缺件处理和人工终审人；只补问影响下一步的缺项。新建任务不从其他客户案例或历史试点继承配置。
2. 按[工具与身份](references/access.md)核对当前组织、宜搭调用身份、数字员工管理身份和真实执行身份。创建权、可见范围、数据读取权和审批权分别验证。
3. 核对可用测试目标及允许触发的操作。没有测试目标时，先准备规则和只读映射；实际发起申请、评论、审批或通知前落实具体目标与授权。
4. 按[数据与脱敏](references/data-and-privacy.md)生成本次资源映射和规则。示例占位符须替换为本次真实回执；公开技能、模板和反馈只保留脱敏内容。

## 实施顺序

1. **准备数字员工**。复用目标组织的已有员工，或按 DWS 官方数字员工技能创建；用户选择运行方式后再发布或连接。员工发布、身份登录、连接和实际处理分别验收，见[工具与身份](references/access.md)。
2. **接入源流程**。用 `use_skill("yida-create-process")` 新建流程，或用 `use_skill("yida-process-rule")` 修改已有流程；人员与节点细节按需加载 `use_skill("yida-flow-node-config")`。来源必须回读为 `formType=process`，数字员工是实际预审节点处理人，后续保留有权人员的人工终审节点。先核对新版本与已有实例的生效范围。
3. **验证一笔申请**。在授权测试目标发起申请，确认源流程实际生成任务且分配到该员工，再按[预审与运行](references/operations.md)验证齐件、缺件、补件和人工确认。创建员工或保存流程不能代替任务投递验证。
4. **按需配置台账与工作台**。用户需要跨应用跟进时，再按操作加载 `use_skill("yida-create-form-page")`、`use_skill("yida-form-view")` 和 `use_skill("yida-canvas-custom-page")`，落地[工作台与原生详情](references/workbench.md)。数据读写加载 `use_skill("yida-data-management")`；应用级通道仅在实际接口需要时配置。
5. **接入运行环境**。先手动跑通，再按已确认的消息触发或定时范围接入 DWS 与宿主支持的执行环境。核对该环境实际具备工具、身份和数据权限；本地连接不能承诺电脑休眠时或全天在线运行。
6. **交付与恢复**。提供本轮实际可用的数字员工或工作台入口，说明已验证来源、动作与运行方式，以及影响使用的未完成项。资源 ID、字段映射、规则版本和非敏感回执留在本次受控工作目录，续做时按这些信息恢复。

## 完成判定

- 预审动作在该员工的授权节点发生，人工终审由有权人员处理；审批建议、已写评论和真实节点动作分别记录。
- 统计仅覆盖明确提交且已受理的申请；员工身份、来源应用、源实例关联可核验。助理状态与源流程状态分列，源状态以原流程为准。
- 配置保存、页面发布、浏览器操作与自动触发分别记录实际证据。未验证的来源、宿主和无人值守运行保持待验证。
