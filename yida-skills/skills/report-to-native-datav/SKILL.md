# 原生报表转原生 DataV 大屏

交付可同时打开的原生报表和原生大屏，并证明对应图表的维度、指标、聚合、时间粒度和筛选一致。使用业务名称，例如“销售经营分析”“销售分析报表”“销售分析大屏”。

本技能通过 `use_skill` 按需加载 `yida-report` 和 `yida-datav`。CLI 支持报表创建和读取、大屏资源管理、已有宜搭数据源图层的查询更新；图层创建、首次数据源绑定、布局和蓝图在原生设计器完成。它不是整张报表的一键转换命令。需要原生设计器而当前宿主无法操作时，保留资源和映射记录，明确待完成步骤，不交付自定义页面替代原生大屏。

## 1. 取得报表和数据证据

- 有现成报表时，复用用户指定的 `appType`、`reportId`，执行下方只读命令取得真实组件 `cid`、数据集、字段角色和查询配置。源报表保持原样，目标大屏单独配置。
- 用户明确要求新建一组报表和大屏时，先按 `yida-report` 搭建报表。新建完整应用通过 `use_skill` 加载 `yida-app` 编排应用与数据准备；已有应用不另建应用。没有源报表时先补齐报表，不能只创建大屏就报告转换完成。
- 读取相关源表单的 Schema。使用真实 cubeCode、字段 ID、类型及原生查询元数据；中文标签仅用于显示。样本数据写入遵循用户范围，通过 `use_skill` 加载 `yida-data-management` 并回读，避免重复导入。

```bash
openyida report inspect <appType> <reportId> --json
openyida get-schema <appType> <reportId> --json
openyida get-schema <appType> <源表单formUuid> --json
```

在任务缓存目录保存图表映射和对照结果，包含源 reportId/cid、数据集与真实字段、筛选范围、目标 formUuid/图层 ID、查询和运行结果。数据源认证与分享凭据不写入记录或交付文档。

## 2. 按分析语义配置大屏

先按 `yida-datav` 读取当前应用主题，再创建或复用原生大屏；使用其返回的设计器和预览入口。明暗、画布、文字、面板和图表配色与应用衔接。

为每个源图表建立对应图层。按报表实际内容选择图表，不固定为三张图；总额指标、分组柱图和日期趋势是可用的基本组合。

| 源报表语义 | 原生 DataV 配置与核对项 |
| --- | --- |
| 数据集与字段 | 选择同一业务数据源；在目标应用重新取得其真实数据集和字段，不能跨应用照搬 ID |
| 度量与聚合 | 保留 SUM、COUNT 等聚合方式及字段类型；SUM 与 COUNT 不互换 |
| 分组维度 | 映射分类轴或系列；对照维度值，不依赖两端返回行序 |
| 日期维度 | 保留时区和年/月/日粒度；设置明确排序，逐日期对比数值 |
| 筛选、排序与限制 | 保留固定条件、查询范围、Top N、分页和空值/零值规则；动态筛选还需配置对应控件与联动 |
| 公式、去重、透视、下钻 | 核实目标组件和原生查询是否能表达；缺少等价能力时逐项标明，不降级为不同口径 |

在原生设计器添加目录中实际可用的组件，选择“宜搭数据源”并绑定数据集和字段。DataV 直接对业务数据集做原生聚合；不把报表结果写成静态数组，也不把报表 `dataSetModelMap` 原样提交为 DataV 查询。

已有图层完成绑定后，可用 CLI 读取并调整查询，细节见 [原生宜搭数据查询](../yida-datav/references/native-data-query.md)：

```bash
openyida datav config <appType> <formUuid> --json
openyida datav data <appType> <formUuid> --component <真实图层ID> --json
openyida datav configure-data <appType> <formUuid> --component <真实图层ID> --query-file <任务缓存目录/query.json> --expected-hash <读取结果中的expectedHash> --json
```

以读取的完整 `query` 为基础，只更改已核实的语义字段。CLI 保留原数据源身份和 datasetId；首次绑定、跨数据集切换在设计器完成。哈希冲突先重新读取并核对，不覆盖并发修改；写入结果不确定时按 recovery 查询同一资源，不重新创建。

## 3. 逐图对照并交付

1. 在相同数据范围、筛选、时间区间和权限身份下运行原生报表与大屏。报表 `runtimeQueryVerified` 和大屏配置 `readbackVerified` 分别证明查询可用、保存一致，还须核对实际数值。
2. 按“维度值 + 指标”比较，检查分组行数、聚合值、日期顺序、单位和小数精度。明确分页、缓存和测试时数据变动对结果的影响。值为 0 与空结果分别处理，不按视觉效果擅自隐藏。
3. 例如四条记录：11 月 1 日华东 120、华南 150；11 月 2 日华东 80、华南 50。两端应均为总额 400、华东/华南各 200、每日 270/130。实际任务使用当前业务数据，不能把示例值当作验收结果。
4. 在应用入口和大屏预览检查布局、标题、标签及筛选交互。保存完整截图，返回两端链接和逐图对照表；不一致或不支持的项目保留在交付结果中。用户明确要求发布启用时，按 `yida-datav` 单独执行发布并核对。

完成条件：报表和原生大屏均可访问；每项要求的图表已配置并逐项记录实际对照结果；布局和查询范围已检查。只读回配置、只完成一个图层或只有大屏时，报告对应进度，不能声称整张报表转换完成。
