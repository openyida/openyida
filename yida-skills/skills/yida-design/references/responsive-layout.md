# 自定义页面响应式布局

设计、Canvas、历史 JSX 和已有页面美化共用本规则。让内容和操作适应当前容器，保留项目主题和密度。门户、工作台、列表、详情和抽屉中的自定义内容均按下文设计、实现和验收。

## 先确定任务与各场景的呈现

Fast、Plan 和单页设计共用以下五步。先读 PRD 中的用户、页面任务、必要信息和操作，再决定各场景的布局。结果统一写入下方已有设计字段。

1. **明确任务和必要信息**：判断本页主要用于识别、比较、分析、逐条处理还是录入，列出行动前需要同时看见的信息。根据已有需求说明选择依据；断点和组件由 Agent 判断。仅在缺失事实会改变任务或范围时向用户澄清。
2. **安排首屏与主操作**：写清宽屏和窄容器中首先展示的业务内容、主操作位置。为核心内容保留首屏空间，按实际需要分配标题、装饰和筛选区的高度。筛选较多时，可外露常用条件，将低频条件放入展开区，并保留展开入口、已选条件和清除方式。主按钮随操作路径放置，固定底部只用于适合的场景。
3. **按信息关系选择形式**：跨记录比较优先使用对齐表格并保留记录标识；逐条处理可使用摘要列表与详情，写清摘要字段和完整信息入口。趋势图随空间调整图例、标签密度和注释，完整数据保持可查。表格转摘要、筛选收纳均按本页任务选择。
4. **分别处理空间和输入方式**：按容器宽度决定并排、堆叠和比例，按触控、键盘、悬停能力及可用高度调整操作。桌面窄抽屉和手机可以共用单列布局，各自保留适用的交互；触屏空间充足时也可并排。手机操作提供直接点击的入口，并检查软键盘、安全区域、可见焦点和触控间距。
5. **保持风格和操作状态**：各场景沿用文字层级、色彩用途、形状和分组，按任务调整密度与比例。正文和表单限制阅读宽度，比较型工作区利用可用宽度，辅助面板按内容确定宽度。返回列表或放宽容器后，恢复筛选、页码、选中项、草稿和焦点。

### 写入已有设计字段

| 已有字段 / design.md 要点 | 写入内容 |
| --- | --- |
| `firstScreenFocus` / 首屏焦点 | 首先看到的业务对象、判断信息及强调方式；窄屏如何保持重点 |
| `layout` / 布局 | 区块主次、需同时可见的信息、宽度依据，以及内容变多或文字变长时的排列方式 |
| `primaryAction` / 主操作 | 主次动作位置、收纳入口、反馈与返回路径 |
| `responsive` / 响应式 | 宽屏、窄容器、触屏的实际变化和理由；重排条件、信息入口及状态保留 |
| `acceptanceChecks` / 验收 | 具体操作和预期结果，覆盖核心内容、长内容、完整操作路径和状态保留 |

例如财务对账页可写：“核对账面金额与实收金额，差额列与记录标识相邻；窄容器仍保留列对齐，表格局部横滑且有剩余列提示。查询为主操作，清空为次操作；宽窄切换后已选记录和筛选值不变。”逐条处理页则可选择摘要与详情。按这种具体程度描述当前页面，配色、布局和业务字段沿用本页设计。

### 新建与已有页面的边界

- 新页面在已授权任务和平台能力内设计呈现方式。
- 已有页面保留原字段、操作、模块、权限和业务状态。折叠内容提供明确入口，所有宽度下均可访问完整信息；禁止用宽度变化静默删除内容。
- 调整表格形式、筛选收纳或打开方式前，先写入设计并按已有页面优化流程确认、备份后实施。尚未确认这些调整时，沿用原表现，仅作换行、堆叠和局部滚动。
- 超出 UI 范围的交互或业务变更交回 PRD，获得相应授权后再实施；响应式改造授权不包含业务变更。

## 再确定可用宽度和重排方式

在已有 `design.md` 的布局、响应式和验收段落写清：哪些区域并排、何时换行或堆叠、堆叠后的顺序、表格如何滚动、哪些面板需要等高。设备适配说明复用这份文档和已有字段，写出具体行为。

- 按内容容器的实际宽度设计，覆盖平台侧栏展开/收起、拖拽调宽、抽屉和 iframe。宽屏中的窄抽屉也按自身空间选择单列或并排。
- 根据控件最小可用宽度、文字长度、列间距和主内容阅读宽度决定重排点。优先复用项目断点；项目未定义时，按本页内容确定并记录。
- 优先用 Grid/Flex 的自动换行和可收缩列解决布局；子项设 `min-width: 0`，需要弹性宽度的网格列使用 `minmax(0, 1fr)`。仍需分级变化时，在运行环境支持的前提下使用容器查询；使用媒体查询时额外核验窄抽屉等容器场景。
- 重排保持业务阅读顺序、DOM 顺序和键盘焦点顺序一致；使用 CSS `order` 时也核对这三种顺序。原有字段、操作和模块保持可达，收纳内容遵守上方确认与入口规则。

## 筛选栏和组合控件

| 可用空间 | 布局规则 |
| --- | --- |
| 足够并排 | 标签和控件分层排列；同一行控件外框上下边缘对齐，按钮与输入控件底边对齐 |
| 一行放不下 | 字段组自然换行，操作区跟随换行；保留字段最小可用宽度，按钮文案完整可见 |
| 窄容器 | 字段按顺序纵向排列并撑满可用宽度；查询、清空等操作在容器内并排或换行 |

- 同组 Input、Select、日期控件和 Button 使用一致的组件尺寸与主题高度；统一标签字号、行高和标签到控件的间距。`Input.Search` 等组合控件一起检查外层、内部输入框、附加按钮和图标的尺寸。
- 标签、控件、帮助/错误信息各占独立布局位置。同排字段可共享标签行和控件行；标签行容纳最长标签，按钮与控件行对齐。错误信息在控件下方展开，输入框继续保持对齐。
- 无标签的操作区直接用布局对齐控件行。对齐由 Grid/Flex 完成，标签、空格和外边距仅承担各自的内容或间距用途。帮助/错误信息随内容增长，并为下一行留出空间。
- 单行控件按主题高度保持一致；多行输入、长标签和反馈内容自然增长。空间不足时换行或堆叠，保留完整文字、可读字号和可用点击区域。
- CSS 限定在当前页面或组件内；组件库内部结构使用当前版本支持的配置/样式入口。禁止用全局 input/button 选择器改变原生表单。

## 主辅面板与分页

- 宽屏下，同一排且需要形成整体的主辅面板采用 Grid/Flex 拉伸外框；卡片内部纵向排列，主体可伸展，分页/底部操作用剩余空间置底。表格行和列表项保持自然高度。
- 面板高度由真实内容和 CSS 布局决定，等高交给 Grid/Flex。独立区块、连续文章和瀑布流保持各自的自然高度。禁止添加假数据填补空白。
- 宽度不足时主辅面板转为上下排列；按已确定的任务顺序展示，清除用于桌面等高的固定高度、最小高度和空白占位。单列时各面板由实际内容决定高度，分页接在内容之后。
- 内容差异过大时调整列宽、分组或堆叠时机，使空白与实际内容相称。布局改变时保留记录、`pageSize`、排序、筛选和分页状态，禁止为对齐改动业务数据。
- 卡片默认随页面滚动，独立滚动仅用于已明确设计的区域。工作区本来有受限高度时，按 [页面与导航连续性](page-continuity.md) 让各级父子容器都可收缩，并保持单一主滚动区域。

## 内容增长、表格与浮层

- 长标题、帮助文字和错误信息自然换行；无空格的长编号或链接设置合适的断行策略。只在已有明确设计允许时省略文字，并保留完整内容的访问方式。
- 宽表格保留列、数据和操作，通过表格自己的容器横向滚动；父级保持可收缩，页面宽度适应容器。出现溢出时修正列宽与容器布局，保持完整内容、键盘操作、固定列和行内按钮可达。
- 空数据、加载、错误和正常内容使用同一外部布局。空态保留必要说明和操作，高度随实际内容收敛；加载时替换内容区并保留查询状态。
- 抽屉和弹窗中的自定义内容按自身宽度重排，检查下拉面板、日期面板和提示能完整显示。局部问题在当前页面内修复，禁止修改平台父容器或跨 iframe 注入样式。
- 优先保留同一组件树，用 CSS 调整排列，保持组件 `key` 和业务区域挂载状态稳定。切换宽度后，筛选、页码、选中项、未提交内容和焦点保持，原请求及触发次数不变。

## 复用模板与 CLI 诊断

Canvas 页面先按当前设计组织内容，需要参考实现时获取模板，并按需复用其中的布局片段：

```bash
openyida sample openyida-page-template canvas-responsive-layout --output .cache/samples/canvas-responsive-layout.jsx
```

模板提供筛选排列、主辅布局、局部滚动和命名容器查询等独立片段。只选取当前业务需要的片段，保留原业务组件树。断点使用本页内容的最小可用宽度，模板数值仅供参考。

优先用 CSS 完成重排。图表等组件需要读取实际宽度时，再复用 `useContainerLayout`；它会合并同一帧的测量通知，并在卸载时清理监听。图表收到容器宽度变化后调用自身 `resize`，尺寸随容器持续更新。

设计决定页面结构，模板提供实现参考。CLI 检查确定的工程风险，首屏重点和视觉效果通过实际页面另行验收。

`openyida compile <页面.canvas.jsx> --json` 与普通页面的 `check-page` 会给出以下非阻断诊断：只按视口宽度重排、`ResizeObserver` 未清理、480px 以上固定宽度、整页 `scale/zoom`。这些诊断为 warning，需按页面用途判断。确认属于视口级抽屉、固定画布等合理用法后，再使用消息中的 `openyida-responsive-*-ok` 标记；普通布局问题先修复，禁止用标记跳过问题。

## 实际页面验收

按本页实际布局检查以下组合，记录实际容器宽度、操作和结果。编译、截图和交互检查分别记录，只有执行过的检查才能标为通过：

1. 宽屏、每个重排点前后及目标最窄容器；同时测试平台侧栏展开/收起和实际抽屉调宽。缩窄后再放宽，布局能恢复，无页面整体横向溢出。
2. 短/长标签、长标题和帮助/错误信息：标签与控件层次清楚，同排控件边缘一致，搜索组合按钮等高，操作无裁切或遮挡。
3. 主辅面板内容一多一少：宽屏需要等高的外框共边，分页位置合理；单列随真实内容自然增长，表格行和列表项保持自然高度。
4. 正常多条、单条、空数据、加载和失败状态；宽表格只在自身容器横向滚动，完整字段与操作仍可达。
5. 键盘遍历、放大文字或浏览器缩放后，内容与操作仍可用；调整宽度前后的筛选、分页、选择和草稿保持，原事件、请求参数及触发次数不变。
6. 至少记录 360、600、768、1024、1280、1600px 及实际重排点前后；这些数值用于测试覆盖，布局断点仍按本页内容确定。桌面宽视口中另测同样宽度的侧栏、抽屉或 iframe，确认布局随内容容器变化。
7. 按本页主任务实际走一遍：找到判断信息、执行主操作、展开收纳内容、返回原位置。对比同宽桌面容器与触屏，确认操作可直接点击；真实移动端另验软键盘、安全区域和焦点。用截图判断视觉层级，用真实操作验证功能；禁止仅凭生成文案、静态断言或截图评分宣称运行态通过。

已有页面按 UI 美化流程先展示宽窄两种效果及必要的换行状态，经确认、备份后实施。只检查过源码或示意图时标记“响应式待运行态验证”；用本地样例或只读方式准备状态，不提交真实业务数据来制造测试场景。
