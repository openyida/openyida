# 读取视觉设计输入

完整应用视觉设计读取已确认的 `.cache/openyida/<项目名>/requirement-brief.json`，沿用 visualSelection 准备基础主题；业务页面的任务和区块确定后补齐逐页视觉绑定。

## 检查

1. 文件存在且 JSON 可解析，`schemaVersion=1`。
2. 读取行业、目标用户、业务目标、核心功能、业务对象、页面场景、品牌和色彩偏好。
3. 读取 `userTasks` 和 `entryRecommendation`，沿用规划准备写入的导航决策，服务与管理体验按实际任务设计；平台导航或自定义导航不再交给用户选择。按已确认范围设计；自定义页面生成逐页场景规则，表单与流程沿用应用主题。
   - 读取已有的使用环境、操作频率、需同时查看的信息和任务中断后的返回要求，区分桌面工作区、嵌入式窄容器和手机触控。
   - 优先依据现有上下文作出选择并记录理由。环境未知时注明假设，同时覆盖宽窄布局；禁止将假设标为用户已确认事实。
4. 会改变视觉方向的 `openQuestions` 未解决时，暂停生成视觉设计并交回 `yida-app` 处理。

## 产出

形成视觉输入摘要：主题目标、视觉气质、页面场景候选、信息密度、设备约束和显式范围。随后进入主题、结构、视觉状态和 `design.md` 输出步骤。
