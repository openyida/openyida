# 视觉脚手架配方库

本文件把高质量页面的视觉结构沉淀成可执行槽位。设计阶段输出 `visualScaffold` 时，从这里选择一套配方，再把当前业务对象、字段、动作和状态填进去。实现阶段按槽位写页面，不复制示例业务文案、不套默认卡片墙。

## 使用规则

1. 先按页面场景选择一套配方。
2. 把 `contentBlocks` 映射到配方槽位；工作台、首页、门户、看板、展示页和业务入口页推荐 8-10 个区块以上。如果业务是窄场景或用户要求精简，可以减少区块，并在 Step 4 说明取舍。
3. 把配方写入 `design.md` 的 `visualScaffold`：`layoutRecipe`、`surfaceMap`、`sectionRhythm`、`densityRule`、`breathingRule`、`componentRecipe`、`emptyStateRecipe`、`responsiveSlots`、`acceptanceChecks`。PRD 只引用 `designFile/designRefs` 和主题风格摘要。
4. 实现阶段逐项消费，不从“高级 / 简洁 / 好看”等形容词直接写 CSS。
5. 默认业务页采用圆润高密且有呼吸感的规则：卡片 padding 默认 22-28px 且必须大于 20px，卡片与卡片的 gap 默认 12-18px 且必须小于 20px，卡片圆角范围 0-32px，控件 10-14px；状态摘要、动作条、列表和空态必须紧凑，间距服务分组和扫读，不用额外 margin 或空白高度撑面积。

## 源码级槽位

`visualScaffold` 不只描述页面长相，还要让实现阶段能直接写出结构。每个配方都必须补齐下面这些源码级槽位：

- `rootShell`：页面外层背景、最大宽度、是否全屏、是否显示平台导航后的内容宽度。
- `prioritySurface`：首屏最大视觉锚点，例如主趋势、主任务、主对象摘要或主视觉区，不能只是标题。
- `statusPrimitive`：紧凑指标、状态胶囊、数据在线、更新时间或主健康分。
- `actionPrimitive`：主操作、次操作、高频动作条或批量动作条。
- `contentPrimitive`：表格、列表、任务流、事件流、排行、时间线、图表或详情预览。
- `contextPrimitive`：右侧洞察、风险、负责人、说明、下一步建议或关联对象。
- `statePrimitive`：loading、empty、error、未接数据和刷新/登记/补录动作。
- `responsiveRule`：移动端分栏退化顺序和关键区块保留规则。
- `densityRule`：页面边距、卡片 gap、状态摘要高度、列表行高、卡片 padding、空态高度和压缩空白规则。
- `breathingRule`：主区、右栏、工具条、列表和空态之间的呼吸节奏，组内/组间间距、贴边修正和移动端折叠间距。
- `roundedRule`：业务面板、主面板、控件、标签、抽屉和弹层的圆角数值。

没有这些源码级槽位时，`design.md` 不算可实现；先补 `visualScaffold`，再进入页面代码。

## 背景层配方

`backgroundLayer` 是 `rootShell` 的一部分。展示型页面、工作台、看板、门户、官网、登录页和空状态页推荐先考虑背景层，再决定卡片和图表。背景层的目标是让页面有环境感和品牌调性，不是用装饰抢内容；极简近白画布也可以成立，但要通过淡渐变、细线装饰、星芒、插图或内容密度避免像未设计的空白底。

页面背景与卡片背景必须形成明显层次对比，不可相近或相同。默认背景保持浅色调：白色/浅色背景配有边框卡片；浅灰背景（如 `#F3F4F6`）配白色无边框卡片；浅彩色背景配白色无边框卡片；渐变背景配玻璃感卡片。`surfaceMap` 必须同步写清 `surfaceContrast`，避免浅底白卡无边框、同色背景同色卡片或只靠弱阴影区分层级。

| 配方 | 适用页面 | 写入 design.md 的字段 |
| --- | --- | --- |
| `softTintCanvas` | 管理后台、工作台、列表、普通看板 | `baseCanvas` 使用低饱和浅底色或带弱渐变的近白画布；内容区保持白色或半透明面板 |
| `topIrregularWash` | 官网、品牌页、登录页、主页面首屏、空状态页 | `topIrregularWash` 写波浪、斜切、流体色块、有机边界、轻装饰曲线或图形标记；内容仍按规则栅格排布 |
| `radialGlowWash` | AI 产品、SaaS 首页、运营驾驶舱、视觉化工作台 | `glowMap` 写 1-2 个大面积柔和光洗位置和透明度；不使用离散装饰圆球或 bokeh |
| `flowLight` | 科技感看板、数据大屏、核心功能引导卡 | `motionLayer` 写低速流光或光影位移，并写 `prefers-reduced-motion` 静态降级 |
| `organicNoise` | 温暖品牌、生活方式、教育、内容类页面 | `textureLayer` 写微噪点或细纹理透明度，保持文字区干净 |

选择规则：

- B 端工具页优先 `softTintCanvas + radialGlowWash`，让背景淡淡存在，前景操作不受干扰。
- 官网、品牌页和登录页可以用 `topIrregularWash` 做第一屏记忆点，像不规则顶部背景或侧向视觉区。
- 数据可视化深色页可以用 `flowLight` 或细线光效衬托图表，但正文和数字对比度必须达标。
- 空状态页和核心功能引导卡适合用低透明不规则底纹引导视线，同时保留明确主操作。
- 极简工具页可以使用近白画布，但要加局部渐变、细线、轻装饰符号、素材焦点或足够密的信息组织；不要为了满足背景层而硬加大面积彩色背景。
- 背景可以不规则，内容必须规则；不要让标题、按钮、表格、列表和图表跟着背景形状漂移。
- 背景和卡片不可相近或相同：浅底白卡必须有边框，浅灰/浅彩背景用白色无边框卡片，渐变背景用玻璃感卡片。

## 配方 A：运营驾驶舱三栏

适合订单、履约、库存、风险、人效、客服、渠道等运营总控页。目标是一眼看状态、看趋势、看异常、看下一步动作。

### layoutRecipe

- 页面外层：浅色业务底，不套整页大卡片。
- 顶部：左侧标题与副标题，右侧数据状态、时间范围分段、刷新按钮。
- 主体：三栏布局，左侧 260-320px 指标轨，中间 1fr 主图表区，右侧 280-360px 风险与事件流。
- 下方：中间区下挂 2-3 个次级分析面板，左侧指标轨可继续纵向滚动。

### contentBlocks 槽位

1. 页面标题与业务副标题。
2. 数据在线 / 更新时间 / 刷新状态。
3. 时间范围分段。
4. 主健康分或主状态摘要。
5. 左侧指标轨的第一类趋势。
6. 左侧指标轨的第二类趋势。
7. 左侧指标轨的风险或异常趋势。
8. 中央主趋势图。
9. 主图表说明与单位。
10. 右侧风险雷达。
11. 右侧实时事件流。
12. 次级结构图或分布图。
13. 次级进度 / 漏斗 / SLA 面板。
14. 空态行动或数据接入提示。

KPI 子项、图表点、列表行不分别计数。

### surfaceMap

- 标题区：无框区。
- 状态胶囊：浅底描边胶囊。
- 左侧指标轨：细线面板内纵向小面板，每个小面板 116-150px。
- 中央主图：大细线面板，图表区域高 360-520px。
- 右侧风险：细线面板，异常项使用左侧语义色竖条。
- 事件流：列表行 + 分割线，不做大卡片。
- 次级分析：细线面板或浅底条，数量少而有主次。
- 圆角：卡片范围 0-32px，业务面板默认 20-24px，指标轨小面板 18-20px，图表主面板 24px，状态胶囊 999px。

### sectionRhythm

- 首屏先读标题，再读状态胶囊，再扫左侧健康指标，最后看中央趋势和右侧风险。
- 卡片间 gap 12-18px 且小于 20px，面板 padding 22-28px 且大于 20px。
- 主图占最大视觉面积，风险项和事件流靠右形成持续扫描。
- 如果首屏信息少，优先压缩面板高度或补充事件流/风险说明，不拉大 margin。

### componentRecipe

- 指标数字使用 `tabular-nums`，主数字 48-72px，辅助数字 28-40px。
- 小趋势可用迷你柱、迷你折线或浅色背景形，不用彩色图标方块。
- 主图使用一条主色实线、一条目标虚线、一条风险语义线，颜色不超过 4 个。
- 风险卡使用语义色竖条 + 等级标签 + 数字，不使用高饱和整卡背景。
- 事件流使用时间 + 标题 + 简短说明，保持列表密度。

### emptyStateRecipe

- 数据为空时保留结构，但用薄空态行、刷新按钮、登记入口或数据接入提示承接。
- 空态高度默认 88-120px；禁止用 160px 以上空白大面板只写“暂无数据”。

### acceptanceChecks

- 三栏比例存在，不退化为四张等宽 KPI 卡。
- `contentBlocks` 推荐 8-10 个区块以上，不作为硬门槛。
- 首屏有主图、风险、事件流和动作入口。
- 左侧指标轨不是四个大白卡。
- 右侧事件流不是空白卡。
- 主色跟随应用主题，语义色只用于风险、告警和成功。
- 源码中能落成 `rootShell`、`prioritySurface`、`statusPrimitive`、`contentPrimitive`、`contextPrimitive` 和 `statePrimitive`。

## 配方 B：任务工作台双栏

适合学生管理、班级运营、项目协作、审批待办、人事行政、门店日常等“进来先处理任务”的首页。

### layoutRecipe

- 顶部：克制标题、角色/日期上下文、主操作。
- 上区：紧凑状态摘要 + 筛选条件 + 高频动作条。
- 主体：左侧任务/最近记录列表，右侧上下文、提醒、进度或洞察。
- 底部：动态、异常、空态行动或辅助链接。

### contentBlocks 槽位

1. 标题上下文。
2. 用户 / 角色 / 日期信息。
3. 班级、项目、门店或周期筛选。
4. 紧凑状态摘要组。
5. 主操作条。
6. 待处理列表。
7. 最近记录列表。
8. 风险 / 异常提醒。
9. 进度或完成率面板。
10. 业务动态流。
11. 右侧上下文面板。
12. 空态行动。

### surfaceMap

- 状态摘要：64-88px 圆润紧凑条，不做大卡片；横向占满时必须补充趋势、更新时间、筛选或风险状态。
- 主操作：按钮组或工具条，40-56px 高。
- 列表：44-56px 列表行、表格或双列队列。
- 右侧：20-24px 圆角细线面板或浅底栏，承接风险、负责人和下一步动作。
- 空态：列表内薄行或右侧提示条，高度 88-120px 内。

### densityRule

- 页面边距 20-28px，栅格间距 14-18px，区块间距 16-20px。
- 卡片 padding 22-28px 且大于 20px；卡片间 gap 12-18px 且小于 20px；任务列表行内距 10-14px。
- 大圆角用于面板性格，不用于放大空白；内容不足时压缩高度，或补最近记录、动态、风险、负责人、说明和下一步动作。

### acceptanceChecks

- KPI 组只算 1 个区块，快捷入口组只算 1 个区块。
- 页面可见任务或最近记录，不只有指标和入口。
- 至少一个右侧上下文或提醒区。
- 没有大面积空白容器。
- 首屏同时具备状态摘要、动作条、任务/记录承接区、右侧上下文和可执行空态。
- 圆润形状和紧凑密度同时成立：卡片圆角在 0-32px 内，卡片 padding >20px，卡片 gap <20px，没有额外 margin 或空白高度撑出的空白。

## 配方 C：主从管理台

适合客户、订单、学生、资产、库存、工单等对象管理页。

- layoutRecipe：顶部筛选工具栏 + 左侧列表/表格 + 右侧详情预览 + 底部批量/分页。
- surfaceMap：筛选无框或浅底条，列表使用表格/密集行，详情预览用细线侧栏。
- componentRecipe：筛选受控、行状态标签、行操作折叠、详情抽屉、批量动作条。
- acceptanceChecks：筛选、列表、详情、批量动作、空态、错误、分页、主操作都存在。

## 配方 D：经营分析看板

适合管理层看全局、复盘经营、汇报指标。

- layoutRecipe：顶部结论条 + 主指标组 + 主趋势图 + 排行/明细 + 洞察建议。
- surfaceMap：核心结论可以独立突出，其他指标保持中性底；主图和洞察面板使用 20-24px 圆角，排行/明细使用紧凑表格或列表行。
- componentRecipe：KPI 有主次，图表有单位和时间范围，排行有业务对象，洞察有证据和建议。
- acceptanceChecks：核心 KPI 明显高于次级指标，不出现 4-6 张等大彩色卡，也不出现内容稀疏的大空白图表壳。
