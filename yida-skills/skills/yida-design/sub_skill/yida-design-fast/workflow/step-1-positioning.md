# Step 1：分析需求和资源

> 先明确这是一个什么宜搭应用、服务谁、解决什么核心任务。设计从业务对象出发，不从固定截图出发。

## 判断应用类型

| 类型 | 典型页面 | 设计重点 |
| --- | --- | --- |
| 企业管理类 | 工作台、列表、详情、流程表单、配置页 | 信息密度、操作效率、状态可见 |
| 经营分析类 | 看板、排行、趋势、预警、明细下钻 | 指标口径、图表层级、异常提醒 |
| 流程审批类 | 申请表、审批表、待办页、流程详情 | 填写路径、节点状态、处理动作 |
| 数据采集类 | 移动录入表单、扫码登记、批量导入、提交结果页 | 快速录入、校验反馈、弱网可读 |
| 客户服务类 | 客户列表、工单池、服务记录、回访表 | 客户上下文、处理优先级、跟进记录 |
| 库存进销存类 | 商品管理、订单管理、库存预警、出入库明细 | 库存水位、状态流转、明细追踪 |
| 项目协作类 | 项目看板、任务列表、里程碑、日报周报 | 进度透明、责任人、风险提醒 |
| 资产设备类 | 设备台账、巡检记录、维修工单、资产详情 | 设备状态、位置、责任人、维修历史 |
| 教育培训类 | 课程首页、报名表、学习记录、证书管理 | 报名转化、学习进度、结果查看 |
| 知识内容类 | 知识库、公告、制度文档、问答入口 | 分类导航、搜索、阅读层级 |
| 监控指挥类 | 数据大屏、告警列表、处置工作台 | 实时态势、风险层级、投屏可读性 |
| 官网门户类 | 官网、落地页、案例、线索表单 | 首屏主张、真实素材、信任背书 |
| 活动报名类 | 活动首页、报名表、名单管理、签到页 | 活动信息、报名入口、名单状态 |
| 轻量工具类 | 计算器、查询页、配置工具、导入导出页 | 单任务效率、输入输出清晰、错误提示 |

## 梳理用户与任务

- 核心用户：角色、职业/部门、使用场景、痛点。
- 核心功能：1-3 个最关键功能，先保证主链路可用。
- 业务对象：客户、订单、项目、工单、商品、门店、设备、合同等。
- 宜搭资源：需要哪些原生表单、流程表单、自定义页面、报表或权限。
- 参考对象：有竞品/参考案例时，只提炼布局、交互、风格和优缺点，不照搬。

## 列资源蓝图

完整应用设计要先把“需要什么资源”说清楚，再进入视觉细化。资源蓝图使用业务语义，运行后 ID 由实现阶段记录。

| 资源 | 设计口径 | 例子 |
| --- | --- | --- |
| 主页面 / 首页 | display 自定义页面，承担应用第一入口 | 经营工作台、CRM 首页、项目驾驶舱 |
| 业务页面 | display 自定义页面，承担看板、列表、详情、官网或大屏 | 订单看板、客户列表、商品详情、品牌官网 |
| 普通表单 | 原生表单，承担数据录入、编辑、校验和列表数据来源 | 商品管理、客户信息、订单管理 |
| 流程表单 | 原生流程表单，承担审批、流转、节点处理 | 请假申请、采购审批、工单处理 |
| 报表 | 原生报表或图表能力，承担汇总分析 | 销售报表、库存预警报表 |
