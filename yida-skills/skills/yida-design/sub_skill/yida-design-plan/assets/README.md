# build-plan.html UI 规范

## 生成方式

`assets/build-plan-template.html` 是预置 HTML 模板，包含固定布局、样式与交互。`openyida design-plan materialize` 从同一版本的计划生成 PRD、设计文档与 HTML；渲染器一次填入标题、目录和完整正文。基础关系图与正文随文件生成，图表增强脚本异步加载，网络等待不阻塞目录和基础图交互。

## 用途

仅在维护 `assets/build-plan-template.html`、`assets/icons/` 或 `scripts/render_build_plan.py` 时读取。正常生成搭建计划时由确定性渲染器消费 `build-plan.json`，不需要把本说明加载进运行时上下文。

## 结构边界

HTML 本体只包含：

```text
顶部目录 + 下方结构化内容
```

不得包含：

- 对话区
- 编辑按钮
- 生成应用按钮
- 顶部工作台
- 聊天输入框
- `ask_human` 过程
- 确认生成 / 继续调整按钮

这些属于外层产品流程。

## 布局

- 顶部目录使用居中的悬浮胶囊样式，保持紧凑的单行吸顶导航，不占用正文横向空间。
- 正文为白底全宽内容区，随视口宽度自适应，不设置固定最大宽度。
- 正文 `.content` 的桌面端内边距统一为 32px。
- `.content` 与各章节设置 `width: 100%`、`min-width: 0`，避免表格或图形撑破网格布局；超宽表格在自身容器内横向滚动。
- 顶部目录使用轻边框、半透明白底、背景模糊和柔和双层阴影，与正文形成悬浮层次。
- 页面背景使用白色或极浅灰，整体克制、清晰、偏产品文档。

## 顶部目录

- `.top-nav` 固定在视口顶部并水平居中，宽度随内容收缩，最大宽度为视口减 32px；使用全圆角胶囊轮廓。
- 胶囊距离视口顶部 12px，内部纵向内边距 6px、横向内边距 8px，整体高度保持紧凑。
- `需求&计划`、分隔线和 4 个菜单项横向排列；目录宽度不足时在目录自身横向滚动，不挤压正文。
- `需求&计划` 使用正常字重和三级辅助色，与首个菜单项之间使用浅色竖向分隔线。

固定 4 个主章节：

```text
需求总览
数据模型
业务流程
页面规划
```

每项包含：

- 章节图标，优先使用 `assets/icons/` 中对应 PNG，不使用 ASCII 符号替代；图标尺寸固定 16px，并与标题首行上下居中对齐，不跟“标题 + 副标题”整体居中
- 标题：14px，一级字体色固定为 `#181C1F`
- 导航不展示副标题，避免增加顶部高度；副标题语义仍由章节正文说明承担
- 菜单项纵向内边距为 8px、横向内边距为 12px，不设置额外最小高度
- 菜单项之间的横向间距为 4px
- Hover 和键盘聚焦态使用浅灰背景和全圆角胶囊轮廓

副标题建议：

- 需求总览：应用概述、业务全景图
- 数据模型：表单、字段、属性
- 业务流程：审批流、自动化流
- 页面规划：页面总览与自定义页详情

顶部胶囊左侧显示灰色小标题 `需求&计划`，字号 14px，使用正常字重，不加粗。目录项默认保持透明背景，Hover 或键盘聚焦时使用浅灰色子胶囊提示。截图中的右侧圆环是搭建计划生成过程的 loading 态，属于外层产品流程，最终 `build-plan.html` 导航中不要展示。

顶部目录使用原生锚点，不依赖 JavaScript 切换章节。点击目录项时：

- 滚动到对应章节标题。
- 四个章节始终纵向平铺，便于连续阅读、全文搜索和打印。
- URL 保留章节 Hash，可直接分享对应章节位置。
- 正文滚动时必须联动顶部目录：导航下方 24px 的判定线进入哪个主章节，该章节锚点就切换为选中态；页面滚动到底部时固定选中最后一项。
- 选中态使用浅蓝胶囊背景和 `#0066FF` 标题，并设置 `aria-current="location"`；窄屏下当前锚点应自动横向滚动到可见区域。
- 点击锚点、浏览器 Hash 变化、窗口尺寸变化与手动滚动都必须触发同一套状态计算，不能出现正文位置和锚点选中态不一致。

## 正文

正文内容字号层级固定为：

- 章节大标题：20px。
- 小节及卡片标题：16px。
- 正文、列表和表格：14px。
- 辅助描述、章节说明、灰色提示和触发信息：12px。

四个章节大标题必须复用顶部 Tab 对应的同一 PNG 图标：需求总览、数据模型、业务流程、页面规划一一对应，不新增另一套图标。正文标题图标尺寸为 20px，与标题文字垂直居中，间距为 10px；图标仅作装饰并设置空替代文本。

标题与紧随其后的描述文字垂直间距固定为 2px，包括章节标题与章节说明、数据模型标题与一句话描述、详情卡片标题与定位描述；不要让段落默认外边距扩大该间距。

正文字体颜色层级固定为：

- 一级文字 `#181C1F`：章节标题、小节标题、卡片标题、正文、列表、表头和表格内容。
- 二级文字 `rgba(24, 28, 31, 0.6)`：仅用于确有必要弱化、但不属于辅助描述的次要信息；正文默认不使用。
- 三级辅助文字 `rgba(24, 28, 31, 0.4)`：章节说明、灰色辅助描述、触发信息和状态提示。

每个章节使用：

- 标题
- 灰色说明文案
- 结构化内容组件

组件选择：

- 需求总览：文档式小节流，包含应用概述、业务全景图、数据模型、业务流程、权限、导航菜单、视觉设计
- 数据模型：圆角字段表
- 业务流程：流程卡片
- 页面规划：页面总览表 + 自定义页面详情卡片；详情展示页面定位、核心任务、内容优先级、功能区块、首屏结构、标志性交互、页面模式和权限

页面详情只展示用户可理解的结构说明，不得出现“模板”“预设”、`preset / adapted / custom`、页面模式内部 ID、主题 key、文件路径或其他生成器术语。内部页面模式必须转换为“聚焦填报页、列表与详情页、分类信息页、紧凑工作台”等业务化名称；内容丰富度和信息密度的英文枚举也必须转换为中文。

## 表格

- 表头浅灰背景。
- 表格外框圆角。
- 行列边界清晰但颜色轻。
- 空值显示 `-`。
- 不使用斑马纹，保持安静。

字段表固定列：

```text
字段 | 字段类型 | 必填 | 默认值/选项 | 关联关系 | 分组 | 说明
```

页面总览表固定列：

```text
页面名称 | 类型 | 用途
```

## 需求总览摘要

需求总览中的“数据模型、业务流程、权限、导航菜单、视觉设计”必须使用单列纵向排列，不使用卡片宫格。整体视觉放在“视觉设计”，逐页视觉应用放在对应页面详情。

需求总览布局：

- 正文不要出现额外全局项目大标题，当前页直接从“需求总览”章节标题开始；章节说明固定为“确认应用定位、业务结构与整体方案”。
- “应用概述”小节包含灰色说明和一段应用描述。
- “业务全景图”小节包含灰色说明、可选简短说明和表关系卡片图。
- 后续摘要小节只用标题、灰色说明和短列表，不加外框卡片。
- 小节灰色说明使用稳定、明确的判断维度，不得重复标题、错用其他章节术语或使用“一句话权限”一类过程化占位文案。固定说明为：
  - 应用概述：产品定位、核心用户与待解决问题
  - 业务全景图：业务对象及其关联关系
  - 数据模型：核心表单与数据职责
  - 业务流程：关键流转与自动化规则
  - 权限：角色范围与数据边界
  - 导航菜单：主要入口与使用路径
  - 视觉设计：整体风格、主题色与导航样式

业务全景图必须渲染成“表关系卡片图”：

- 每个节点是一张表 / 表单卡片，使用“表单类型图标 + 表名称”的单行结构。
- 普通表单与流程表单使用两枚不同的 16px 统一线性图标，图标来自 `assets/icons/` 正式资源；类型文字继续保留在数据和无障碍名称中，避免只依赖图形传达语义。
- 节点固定为 36px 高的单行横向布局，左右内边距 12px，图标与表名称之间保持 8px 间距；适应画布只允许缩小，不应把节点放大到超过设计尺寸。
- 节点、图标、连线和关系标签的默认态只使用中性色；仅当前选中的节点、关系与对应路径使用产品主题色 `#0066FF`，避免画布在未操作时出现大面积品牌蓝。
- 一对多连线使用圆角正交走线：从源节点右侧引出 24–32px 后形成共享纵向主干，再以水平分支连接目标节点；同一水平线上的关系保持直线。转角半径为 12px，并使用小尺寸开放式箭头和适当端点留白，避免大范围 U 形绕行或粗重的实心三角。
- 节点必须覆盖全部 `dataModels`，包括没有明显上游或下游的表。
- 节点仅由 `dataModels` 建立，一表一节点；图中节点 ID、关系端点和唯一的“表/表单/信息表”简称映射到已有表。精确表名优先，歧义或未知引用报错，不能把“玩偶商品表”和“玩偶商品”画成两个节点。别名用 `modelName` 明确绑定，图中统一显示完整表名。
- 每条连线必须标注关系类型，例如“包含、关联、产生、承接、依赖、回款跟踪”。
- 图容器按节点布局高度自适应，普通视图最大高度取 480px 与视口高度 65% 的较小值；小图收紧留白，不固定宽高比。默认完整适配，节点不放大超过设计尺寸。
- 容器提供“缩小、放大、适应、全屏”控件和当前缩放比例；适应画布与全屏是独立操作。全屏填满可用视口，支持按钮和 Esc 退出；退出后恢复自适应高度。受限预览环境使用页面内铺满视口的方式。
- 灰底画布容器不设置描边；提示文案直接叠放在画布左上角，不单独占用工具栏行。
- 画布右上角操作集中在一个无描边的悬浮胶囊中，使用半透明白底、背景模糊和柔和阴影；按钮自身透明，Hover / 聚焦时显示浅灰子胶囊。
- “缩小、放大、适应”使用 16px 统一线性图标的纯图标按钮；缩放比例保留百分比文字；“全部关系”使用关系网络图标加文字。所有图标来自 `assets/icons/` 正式资源，按钮保留 `aria-label`，纯图标按钮同时提供悬停提示。
- 缩放控件要支持键盘操作，并为按钮、视窗和图形提供可访问名称。
- 业务全景图统一使用 AntV G6 5.x 组件渲染；6 个以上节点或 8 条以上关系时，节点按 `businessGraph.nodes` 的业务顺序或明确阶段预置布局，不能只按算法层级随机重排。
- HTML 使用固定版本的官方 G6 CDN 产物，并保留无网络或组件加载失败时的静态 SVG 回退；回退视图不得重复推导关系。
- G6 挂载容器初始化时必须保持可测量，渲染完成后执行 `resize()` 和 `fitView()`，并启用 `autoResize`，避免右侧节点因初始宽度错误而被裁切。
- 连线上默认显示关系名称，SVG 基础图与 G6 增强图保持一致；标签使用中性色与浅底，增加列间距避免压住节点。点击节点只高亮相关路径及标签，点击“全部关系”恢复全景。
- 图下方保留完整关系清单；过长标签可在连线上缩略并提供完整提示。点击关系条目定位并突出起点、终点和对应连线。
- 关系清单使用浅灰底承载，不设置区块外边框；内部可点击关系项保留清晰的交互边界。
- 优先使用 `overview.businessGraph.nodes` / `overview.businessGraph.relations` 渲染；缺失时可从字段关联关系和简单 Mermaid `graph LR` 中推断。
- 无法解析时才展示文本兜底。

## 流程卡片

每条流程一张卡片：

- 左上：流程类型标签
- 标题：流程名称
- 右上：触发时机
- 中部：节点链路
- 下部：业务说明和规则说明

流程类型标签：

- 自动化：蓝色轻标签
- 审批流：橙色轻标签
- 业务流：绿色轻标签

## 可访问性与响应式

- 文本字号不小于 12px。
- 正文默认 14px，标题 20-24px。
- 小屏下胶囊宽度为视口减 24px，保持单行置顶并允许横向滚动；HTML 仍保留目录与内容两层结构。
- 不使用负 letter-spacing。
- 内容不可重叠，表格可横向滚动。

## 需求总览中的视觉信息

`build-plan.html` 保持需求总览、数据模型、业务流程、页面规划四章，完整展示用户需要确认的方案；Markdown 为 Agent 提供执行契约。

- 需求总览：应用概述、业务目标、业务全景图、业务与权限摘要、完整视觉方向、色彩和导航、组件与状态、响应式、素材现状和缺口。
- 数据模型：表单、字段、关系、视图、初始示例记录或跳过原因。
- 业务流程：触发条件、节点、业务规则，以及空态、异常和入口交互。
- 页面规划：页面任务、区块、首屏、密度、权限、数据来源、主操作、逐页视觉应用，搭建范围、三种顺序和验收标准。

HTML 与 Markdown 使用同一份解析后的业务交接，显式覆盖优先级相同。页面 ID 转为名称，技术字段转为业务表达；CLI 命令、运行 ID、模板路径、内部版本状态和原始 token 定义保留给 Agent。不得为了精简 HTML 省略用户需要确认的业务、视觉或验收内容。
