# 打印模板指南

原生模板可在宜搭编辑器继续拖改和保存。CLI 保存的是相同资源，无额外的“CLI 发布态”。

原生复制接口在部分环境会复制版式但遗漏字段字典。CLI 仅在新版式与源模板完全相同、且字典确实为空时，对新模板执行一次带备份和版本校验的字典补全，再核对三件套。其他不一致直接报未验证，不盲目覆盖。

## 选择版式

- 订单/报价：document，双栏基本信息，明细表，合计计算字段，签字说明。
- 审批/申请：formal，单栏关键信息、申请说明、审批节点或审批历史，签字区域。
- 收据/领取单：compact，较小字号与内容宽度，关键字段与金额，简短备注。窄内容宽度不等于设置了热敏纸规格。
- 完全自定义：html 区块组织静态 XHTML，把 `{{字段}}` 放在需要的位置。图表、交互脚本、任意浏览器 CSS 不属于原生 PDF 排版契约。
- 追溯与扫码：qrcode / barcode 区块按真实字段生成动态码图。字段网格、明细列也可用 render 属性显示二维码或条形码；字段资格、版本和功能开关与原生编辑器对齐。码图默认尺寸可改，但尺寸过小不保证扫码识别。

## 原生往返编辑

inspect --out 导出完整快照。将快照 content 中的 termContents、termJsonAttr、dictionaryList 三个字段组成新的 JSON 文件，编辑后用 save。宏 ` #macro_<id> `、组件 ID、dictionaryList 中的 id/type/key 必须一致。termJsonAttr.content 是编辑器动态输入组件的 XHTML，并非运行脚本。

restore 接受完整快照或命令自动备份，校验原目标。备份中的 configHash 是旧版本；恢复时 `--expected-hash` 必须用当前 inspect 返回的新指纹。

## 权限与并发

元信息/启停/排序没有统一服务端 compare-and-swap；客户端指纹能发现读取之后已有的变化，不能锁住其他管理员。正文 save 使用平台已有 gmtModified 检查，平台返回 300051 时重新 inspect 并合并，不可剥掉时间戳强制写入。空模板尚无正文时间戳时仍存在首次保存竞争。

新模板的初始使用范围由平台创建接口决定；create 结果中显示 roleMembers。接入面向特定人员的模板时，应在使用前按用户明确指定的范围调整并验证。不得更改组织权益或绕过打印权限。

roleData 是平台权限角色序列，roleValue 是原始值字符串，不是 roleMembers 中的展开成员数组。不要把展示用 roleMembers 直接作为写入参数。复杂角色应先在平台现有范围中确认角色类型及 ID，再提交。

## PDF 检查

render 使用 CUSTOM 类型请求自定义模板，保留平台模板权限校验。返回文件 ID 后，files 的分页结果由平台提供；FINISH 是文件生成状态。用当前环境的 previewUrl/downloadUrl 访问；相对 URL 依附当前 auth base_url，不改成其他组织域名。

本文不承诺创建 Word 模板、叮当模板、批量打印、删除模板、安装字体、下载或发送到人员/群、修改打印额度与物理打印机操作。

字段码图在原生模板中仍使用 img 类型，字段 key 为原字段加 `.qrcode` 或 `.barcode`。原生导入校验需要确认原字段存在、类型符合原生白名单、当前组织码图能力已核实；不能仅因输入看起来是图片而放行。字段网格和明细列同样进行资格校验。宽高写入原生 td-width/td-height 及容器尺寸。正文备份与恢复保留这些信息。
