# 闪记和会议内容转 PRD

## 执行入口

当前 Agent 使用自身的模型能力理解材料并生成 PRD。本地、远端、千问办公、Codex 和托管任务均使用这一流程。

- 已有文本、文件或图片可以直接处理，生成 PRD 无需宜搭登录。
- 用户只提供 taskUuid 时，先加载 `yida-tingji` 读取听记内容，再处理读取结果。读取听记所需的权限与登录遵循该技能。
- 用户提供钉钉文档链接时，用 `yida-document-markdown` 获取正文。听记链接中的 taskUuid 交给 `yida-tingji`。
- 材料无法读取或内容不足以确定任何需求时，说明缺少的内容并请用户补充。
- Agent 生成 PRD 时，不调用 `openyida flash-to-prd`、`openyida ai` 或 `/query/intelligent/txtFromAI.json`。

独立命令行脚本的远端 AI 入口见本文末尾；仅在用户明确选择该入口时使用。

## 生成步骤

1. 读取用户提供的完整材料，识别会议标题、时间、参会人、转写、会议摘要、决策及待办。
2. 提取项目目标、MVP 范围、角色权限、功能、数据字段、流程状态、约束、报表及验收要求。为关键事实保留材料位置或原始措辞。
3. 按 [PRD 输出模板](references/flash-note-prd-template.md) 组织 PRD。材料未涉及的章节说明缺口，将需要业务决策的事项列入「待确认事项」。
4. 使用宿主的文件写入能力保存至 `prd/<项目名>/prd.md`。无法写文件时，提供完整 Markdown 并说明保存能力的缺口。
5. 重新读取产物，逐项核对角色权限、数值、日期、时间、否定条件及例外，确认没有缺章、截断或遗漏材料末尾。
6. 返回 PRD 的可访问位置、需求摘要与关键待确认项。用户确认继续搭建应用时，交给 `yida-app`。

用户直接提供内容时，从读取材料开始执行；不先检查宜搭登录或创建应用。

## 长材料处理

按当前宿主的上下文与文件读取能力分段读取。每段建立需求事实清单，记录来源、明确决策、争议和待确认项，再由当前 Agent 合并清单生成 PRD。

- 按话题、发言或段落拆分；超长单行继续分段，保留所有内容。
- 覆盖会议摘要和原始转写，并核对首段、中段、末段是否都已读取。
- 以业务事实清单衔接各段，合并重复项，同时保留独立规则、具体数值与例外。
- 清单过长时按业务模块分别整理并写入同一份 PRD，最后检查跨模块关联。
- 输出较长时分章节写入文件，再读取整份产物核对完整性。

具体的分段、事实核对和冲突处理见 [材料处理规则](references/flash-note-prompt.md)。

## 事实与推导

- 区分原始转写、自动摘要、讨论建议和明确决策。自动摘要与原话冲突时，保留分歧；只有明确的最终决策可以替代旧结论。
- 保留业务时间、数量、金额、阈值、单位和否定条件。只清理录音定位时间等噪音。
- 按原文记录操作权限。「调整库存」不自动扩大为新增或删除物料的权限。
- 区分触发时间和统计范围。只给出报表生成时间时，将统计截止时间列为待确认。
- 补充的字段、流程或实现建议必须标注为「建议，待确认」，不得作为已经确认的业务规则。
- PRD 只写业务语义。真实 appType、formUuid、fieldId 由后续搭建回读取得，记录在对应 Schema 台账中。

## 独立脚本的可选 CLI

用户明确要求独立脚本通过宜搭 AI 服务生成时，使用现有 CLI。这个命令需要 Node.js ≥ 18 和有效宜搭登录态，会调用 `/query/intelligent/txtFromAI.json`。

```bash
openyida flash-to-prd --file meeting.md --name "物料管理"
cat meeting.txt | openyida flash-to-prd --name "物料管理"
```

| 参数 | 说明 |
| --- | --- |
| `--file`、`-f` | 文本文件路径，省略时读取标准输入 |
| `--name`、`-n` | 项目名称，省略时从生成结果提取 |
| `--max-tokens` | 最终生成的输出上限，默认 8000；过低可能截断文档 |

CLI 输出为 `prd/<项目名>.md`。命令按完整提示词的 6000 字符预算分段提取和分批归并，中间输出最多 768 token，单次请求最多等待 65 秒。生成失败时保留已有 PRD。
