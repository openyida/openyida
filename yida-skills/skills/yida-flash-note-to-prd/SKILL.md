# 闪记需求素材整理

本技能只处理已有会议内容，输出结构化需求素材。最终 `prd/<项目名>/prd.md` 与 `prd/<项目名>/design.md` 由 `yida-design` 生成或更新。

## 触发条件

| 用户输入 | 动作 |
| --- | --- |
| 闪记文本、会议纪要、需求访谈记录 | 提取需求素材 |
| 闪记截图或图片 | 先识别图片文字，再提取需求素材 |
| 钉钉闪记链接 | 提示用户复制全文后粘贴 |
| 只有 taskUuid | 先加载 `yida-tingji` 读取听记内容，再处理读取结果 |

## 铁律

1. **不得凭空生成需求素材**：没有闪记文本、图片识别结果或听记内容时，先让用户补充内容。
2. **不得宣称本技能产出最终 PRD**：本技能输出需求素材；最终 PRD 和 design.md 交给 `yida-design`。
3. **不得忽略 A1 结构化摘要**：会议摘要、待办事项、决策结论优先进入需求素材。

## 工作流程

1. 识别输入类型：文本直接处理，图片先识别文字，链接要求用户粘贴全文，taskUuid 先交给 `yida-tingji`。
2. 提取会议元信息：标题、参会人、时间、背景、决策和待办。
3. 提取业务需求：角色、业务对象、核心流程、字段候选、状态变化、报表诉求、权限边界和待确认事项。
4. 写入需求素材文件：默认写入 `prd/<项目名>/flash-note-requirements.md`；若现有工具只能输出 `prd/<项目名>/prd.md`，必须在文件顶部标明“需求素材草稿，最终 PRD 由 yida-design 生成或更新”。
5. 交给 `yida-design`：让 `yida-design` 消费需求素材，生成或更新 `prd/<项目名>/prd.md` 与 `prd/<项目名>/design.md`。

## 输出要求

需求素材必须包含：

- 会议来源：标题、时间、参会人、输入来源。
- 业务背景：用户为什么要做这个应用或页面。
- 角色与权限：谁使用、谁审批、谁查看。
- 业务对象：表单、流程、记录、报表或页面对象的候选清单。
- 核心流程：从提交、处理、查看到统计的业务路径。
- 字段候选：字段名、字段类型建议、必填性和说明。
- 待确认事项：闪记中没有说清的组织、权限、字段、流程、数据和验收问题。

## CLI 口径

若使用 `openyida flash-to-prd`，先确认命令当前会输出到哪里：

```bash
openyida flash-to-prd --help
```

命令若仍输出 `prd/<项目名>/prd.md`，该文件按需求素材草稿处理。进入正式应用设计前，必须让 `yida-design` 读取并重写最终 `prd.md` 与 `design.md`。

## 完成条件

1. 已得到可读的闪记或会议内容；
2. 已输出需求素材文件；
3. 已提示下一步交给 `yida-design` 生成或更新最终 `prd.md` 与 `design.md`。
