# Fast 简单页面搭建

已明确选择 Fast、需求清楚且主要为少量展示页时，按真实依赖推进。五分钟是减少等待和返工的目标，不是跳过业务、权限、校验或发布验收的理由。

## 范围与准备

保留用户要求的全部视图、交互和移动适配。首页、案例列表/详情、联系方式等展示内容本身不要求新增表单、后台、示例数据写入或角色配置；只有用户要求可维护内容、提交保存、数据库、管理后台、角色/数据隔离等能力时才规划对应资源。已有业务资源按需复用。不能以简单页面为由省掉已要求的数据和权限。

一个连续官网可按入口规划在同一页面实现多个业务视图，共用导航、数据和主题；明确要求独立页面/地址时保留独立资源。示例内容标明示例，不伪装为真实客户案例或数据库记录。

Fast 采用命名主题时，由 yida-design 按 [短输入生成设计](../../yida-design/references/fast-design-spec.md) 输出完整 design.md；PRD 与视觉决策读取同份已确认需求，页名和 pageId 共用。真实宿主支持非阻塞任务或子 Agent 时同时派发；仅同步工具时用一次准备批次写职责明确的文件，不先派发再立即等待整包。没有实际任务编号与重叠区间，不记录为并行。

## 依赖与执行

1. 已确认的主题选择、资源范围与核心交互准备一次，复用同版本已读规则、主题目录、技能路径及能力快照。能力快照已确认登录与运行环境后不再串行执行 env、auth status、auth snapshot 等重复检查；写入仍由 CLI 权限与认证保护。
2. PRD/design 关联校验通过后立即创建或复用应用；主题 CSS 和各页源码准备不依赖 appType，可同时开始。真实 appType 就绪后更新主题，页面只等待自己的资源与真实数据契约；原生表单身份未知时保留待绑定动作，发布前完成绑定。
3. 无依赖的页面同时开发、检查，各自就绪即发布；同一页面保持唯一写入者。仅有同步子 Agent 时不把整页包派发放在主流程前置，按并行能力安排独立代码或主流程继续实现。平台写入通过现有 batch/资源锁，不以 Shell `&` 绕过并发保护。
4. 图片独立准备，沿用整次60秒截止时间与单请求15秒预算；先发布已授权的可用首版，补图只改绑定。生成工具无法取消或返回较慢时继续页面工作，不能连续等待每张图。素材来源按实际工具回执显式传给 asset resolve。
5. 含原生表单入口时先提取完整 form-open-container 模板，整体保留 import、辅助函数与操作，不手工重写抽屉以压缩源码。只按实际功能提取需要的模板，不为展示页引入表单容器。
6. 校验返回的结构化 issues 一次处理，改动后只重跑受影响项。失败恢复保留资源 ID、清单和已发布页面；未知写入先回读，不盲目重复创建。页面发布后统一处理必要导航与入口交付，检查主题、交互和真实链接。

## 耗时记录

分别记录准备/契约、资源/主题、页面源码、编译发布、业务验收与素材的真实开始和结束时间；总耗时按墙钟计算，不能把相交的任务时间相加。规划参考为准备约60秒、资源与主题约45秒、页面实现与编译发布约150秒、验收交付约45秒；实际以记录为准。等待、权限交互、宿主推理、生成工具及平台请求分别标记，不能把全部间隔都算成平台接口耗时。

超过目标时继续完成已授权任务并说明实际瓶颈。完整数据库、角色隔离、审批和多端业务链路按实际复杂度安排，不能沿用展示页预算宣称已经实现五分钟交付。
