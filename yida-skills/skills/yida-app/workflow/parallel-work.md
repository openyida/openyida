# 并行执行

## 可以同时做什么

| 阶段 | 可并行任务 | 何时进入下一步 |
| --- | --- | --- |
| 需求分析 | 读取互不依赖的附件、已知资源与品牌资料 | 汇总事实后，统一询问未决事项 |
| 需求确认后 | 业务对象、字段、流程与页面规划；基础主题、配色、token 与素材策略 | 页面任务和区块确定后，补齐各页设计 |
| 方案可实施后 | 准备主题 CSS（Plan 复用已生成文件）；编写各页面源码；读取已知表单字段 | 主题就绪后配置应用；真实字段就绪后完成数据绑定 |
| 表单创建 | 无依赖表单通过 `create-form batch` 同时创建、回读 | 关联表单和真实字段就绪后创建依赖表单；主流程统一导航排序 |
| 页面实现 | 不同页面的源码与本地检查 | 每页使用独立源码和输出目录；共享导航与组件由一个任务维护 |
| 发布后 | 独立页面的只读配置与数据回读 | 主流程汇总结果，再完成应用级验收 |

首次搭建的必要确认完成后，才启动业务与视觉规划。Plan 还需用户确认当前方案，才能创建和发布资源。

## 调度方式

宿主支持并行任务时，同时启动表中互不依赖的工作，并给出输入、输出路径和完成条件。普通只读工具调用可批量并发。任务开始后，主流程继续做其他独立工作，在需要结果时再等待。

两个任务分别写自己的文件。主流程负责合并、共享配置、发布与导航排序；普通表单按 [批量创建规则](../../yida-create-form-page/references/batch-forms.md) 自动调度依赖。某项失败只重做该项及依赖它的工作。宿主仅支持串行时，按相同依赖顺序执行并复用已有结果。

## Plan 的 CLI 交接

模块确定后按 [按模块更新方案](incremental-preview.md) 立即更新草稿；全部完成后使用 `materialize --from-preview` 汇总校验。下方双片段交接适用于一次收齐业务与视觉的场景。

`design-plan init` 返回 `parallelTasks` 和两个片段文件：

- `business.json`：业务任务填写 facts 中的 overview、dataModels、businessFlows、pages 和可选 execution。可选 meta 仅填写 businessDomain、experienceTopology，完成后设 ready=true。
- `visual.json`：视觉任务填写 facts.visualStyle；先完成基础视觉，等业务片段完成后，按真实页面补齐 pageApplications，再设 ready=true。

两个文件的 base 由 CLI 生成，保留原值；任务读取同一份需求、草稿和主题上下文。业务片段完成后保持稳定，变更时通知视觉任务重新核对页面设计。

主流程收齐结果后执行一次：

```bash
openyida design-plan materialize prd/<项目名>/build-plan.json \
  --business-file prd/<项目名>/business.json \
  --visual-file prd/<项目名>/visual.json --json
```

CLI 校验片段完成状态、来源版本、字段职责和页面对应关系，统一写入源计划、三份文档和主题 CSS。失败时保留原文件；合并成功后，后续修改使用当前计划的 patch 流程。

Fast 的业务与基础视觉同样并行，分别维护 PRD 和设计文件；页面内容确定后补齐各页设计，再由主流程核对交接。

## 耗时记录

记录每项任务的开始、完成和等待时间。并行任务的总耗时按实际起止时间计算。CLI 的 timings 只记录本地生成阶段；模型规划与用户等待由宿主记录。

草稿按模块更新，正式产物在完整校验后一起保存。
