# 宜搭线上变更同步

## 定位

本技能用于把宜搭线上设计器中的人工改动同步回本地项目，形成可维护的 `.cache` Schema、`prd` 记录、页面源码字段映射和风险报告。

这是**拉取、对比、归档、提示风险**流程；默认不发布、不删除、不覆盖线上配置。只有用户在看过影响报告后明确要求发布，才转入对应发布或保存技能。

## 必须先读的技能

执行具体对象同步前，先读取相关子技能文档，禁止凭记忆猜参数：

| 对象 | 必读技能 |
|------|----------|
| 表单字段 / Schema | `yida-get-schema`，必要时读 `yida-create-form-page` |
| 自定义页面源码 | `yida-custom-page` |
| 自定义页面重新发布 | `yida-publish-page` |
| 表单权限 | `yida-form-permission` |
| 流程规则 | `yida-process-rule` 或 `yida-create-process` |
| 页面公开访问 | `yida-page-config` |
| 报表 | `yida-report` 或 `yida-chart` |
| 连接器 | `yida-connector` |
| 集成自动化 | `yida-integration` |

## 禁止事项

- 不要编造 `corpId`、`appType`、`formUuid`、`fieldId`、`processCode`、连接器 ID 或权限组 ID。
- 不要在未确认组织与登录态前执行同步命令。
- 不要把线上编译后的自定义页面代码当成干净源码直接覆盖 `pages/src/*.js`。
- 不要在同步阶段执行 `openyida publish`、删除字段、覆盖流程或保存权限，除非用户明确确认。
- 不要用纯字符串 diff 判断 Schema 语义，必须用 JSON 结构理解字段、组件、权限和配置变化。
- 不要把临时输出写到项目根目录，统一写入 `.cache/`。

## 标准流程

### 1. 确认同步范围

先判断用户改的是哪类对象：

- 应用：需要 `appType`
- 表单 / 字段：需要 `appType`、`formUuid`
- 自定义页面：需要 `appType`、页面 `formUuid`
- 流程：需要 `appType`、`formUuid`，有条件时记录 `processCode`
- 权限 / 报表 / 连接器 / 集成自动化：需要对象类型和对应 ID

如果用户没有给 ID，先在本地 `prd/`、`.cache/`、`project/config.json`、`pages/src/` 中查找已有记录。仍无法安全确定目标时再询问用户。

### 2. 检查环境

执行只读环境检查：

```bash
openyida env --json
openyida login --check-only --json
```

检查重点：

- 当前环境是否能调用 `openyida`
- 是否已有登录态
- `base_url`、`corpId` 是否与项目记录一致
- 当前项目根目录是否正确

如 `corpId` 不一致，先停下来问用户：重新登录到正确组织，还是按当前组织继续同步。

### 3. 快照本地状态

同步前先读取本地已有材料：

- `.cache/*schema*.json`
- `.cache/openyida/**`
- `prd/*.md`
- `project/config.json`
- `pages/src/*.js` 或 `project/pages/src/*.js`

记录目标对象当前在本地的文件位置、字段映射和业务说明。工作区有未提交或用户改动时，保留这些改动，不要整体覆盖。

### 4. 拉取线上状态

表单和自定义页面优先使用：

```bash
openyida get-schema <appType> <formUuid>
```

把新拉取的结果保存到 `.cache/`。命名遵循项目现有约定；没有约定时使用：

```text
.cache/<项目名>-<formUuid>-schema.json
```

权限、页面配置、流程、连接器、集成自动化等对象，按对应子技能提供的只读查询命令拉取；没有稳定只读命令时，在报告中标记为“需人工确认或补充命令支持”，不要猜接口写脚本。

### 5. 对比并分级

将线上最新结果与本地缓存、PRD、源码映射对比，按风险分级：

| 风险 | 变化类型 |
|------|----------|
| 低 | 文案、说明、布局、展示顺序等不影响字段 ID 和运行契约的变化 |
| 中 | 新增字段、选项变化、默认值变化、必填/隐藏/校验变化、视图变化、页面布局中被源码依赖的变化 |
| 高 | 删除字段、字段类型变化、字段 ID 变化、流程节点变化、权限规则变化、连接器鉴权变化、线上直接编辑自定义页面但无法还原源码 |

字段变化报告至少包含：业务名称、旧字段 ID、新字段 ID、旧类型、新类型、影响代码位置。

### 6. 更新本地材料

只做可解释、可回退的本地更新：

- 更新 `.cache/*schema*.json` 为线上最新 Schema。
- 当字段映射唯一明确时，更新页面源码顶部的 `FIELDS` 常量。
- 更新 `prd/<项目名>.md`，追加“宜搭线上同步记录”，记录日期、目标 ID、变化摘要、风险和后续动作。
- 对删除字段、类型变化、无法还原的线上页面编辑，只标记影响点，不静默删除本地逻辑。

PRD 中继续遵守主技能约定：业务语义写 `prd/`，`formUuid`、`fieldId` 等 ID 写 `.cache/`；同步记录中如必须引用 ID，用于审计即可，不要把 PRD 变成 Schema 缓存。

### 7. 本地验证

同步后执行：

- 重新读取被改文件，确认没有误改无关内容。
- 如果改了自定义页面源码，运行 `openyida check-page <源文件路径>` 和 `openyida compile <源文件路径>`。
- 如果只改了文档和 `.cache`，说明无需发布。
- 如果需要把本地源码重新发布到线上，先输出影响和发布命令，等待用户明确确认。

## 自定义页面特殊规则

自定义页面以本地源码为事实源。线上直接编辑后：

1. 拉取线上 Schema 用于审计。
2. 如 Schema 中包含可读 `source`，只在差异清晰时做小补丁。
3. 如只有编译/压缩代码，不要覆盖 `pages/src/*.js`。
4. 报告“线上改动需要人工或 AI 根据运行效果重建到源码”。
5. 重建完成并通过 `check-page`、`compile` 后，再询问是否发布。

## 输出格式

结论优先输出：

1. 同步结果：完成 / 部分完成 / 阻塞。
2. 本地更新文件。
3. 线上变化点，按低/中/高风险分组。
4. 对页面源码、流程、权限或数据的影响。
5. 是否需要重新发布；如需要，只给出待确认的命令，不直接执行。

保持简洁，但必须包含具体 `appType`、`formUuid`、文件路径和无法自动同步的原因。
