# 业务动作的授权与状态约束

隐藏按钮、禁用控件、isAppAdmin、前端角色判断和 URL 都只是界面控制。确认报名、取消、签到、删除等写操作，必须由平台权限配置或真实服务端动作校验当前访问者、目标记录、可修改字段及允许的状态变化。不能把“管理员按钮已隐藏”作为权限验收结果。

## 先建立动作清单，再接按钮

在现有 PRD 或页面实现计划中逐动作记录：业务角色、真实资源和操作、数据范围、可写字段、前置状态、成功状态、实际调用、权限配置/服务端实现位置和验证结果。不新增虚构的权限 API，不把应用管理员身份自动视为业务运营角色。

活动报名示例（最终以真实业务需求为准）：

| 动作 | 授权与数据范围 | 服务端约束 |
| --- | --- | --- |
| 确认报名 | 运营角色，只操作被授权活动的报名记录 | 仅待确认可转已确认；普通参与者不能写确认字段 |
| 取消报名 | 参与者只取消本人记录；代取消需独立授权 | 校验当前状态与取消时限；不能靠请求传入的 userId 判断本人 |
| 签到 | 被授权签到人员，只操作负责活动的记录 | 校验可签到状态；重复请求不能重复计数或产生重复副作用 |

平台通用 updateFormData 可调用，不代表上述业务规则已经满足。核对实际表单权限、字段可写范围和流程规则能否覆盖每一条约束；不能覆盖时，通过已验证的服务端动作或原生审批流程实现。只在前端查询“未重复”再提交存在并发窗口，幂等、版本/状态前置条件须由服务端原子执行。连接器保存凭证也不自动保证记录级授权，不能暴露可让普通访问者任意更新数据的特权接口。

如果真实能力尚不具备，保留说明并禁用对应业务动作，将缺口列为未完成；不要用前端 if、按钮隐藏或成功提示冒充授权完成。页面不携带 CLI 管理员 token，不复制管理员身份执行访问者操作。

## 请求与反馈

客户端只发送动作所需字段，不把整行数据回写；服务端从认证上下文确定操作者并检查目标记录归属。点击后防重复只是体验保护，不能替代服务端幂等。成功后回读权威状态再更新列表和统计；失败不把界面推进到成功状态，保留原数据和可恢复输入。

按接口真实错误契约区分无权限与状态冲突，不假设所有 API 都使用相同 HTTP 状态码。无权限时更新入口可用态、提示原因；状态冲突时重新读取记录并提示刷新，不自动重放写请求。前端不知道权限时先禁用或隐藏，不用乐观放行。

## 多身份验收

使用当前真实访问者的凭证逐项验证：管理员或业务角色的合法操作、普通用户直接调用隐藏动作、替换他人记录 ID、写入未授权字段、过期状态、重复与并发提交。对拒绝用例回读数据和副作用，确认确实未修改。测试普通用户时不能复用 CLI 管理员凭证；匿名仅在页面支持匿名访问时纳入验证。

记录角色、目标、预期、实际返回与回读结果。只有编译、发布、配置回读或管理员正向测试时，权限验收仍为待验证；样例与静态检查不证明线上授权有效。
