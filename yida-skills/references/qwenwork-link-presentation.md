# 千问办公收尾链接展示

## 收尾必做检查

每轮按“核验业务 → 选择入口 → 调用展示工具 → 检查回执 → 最终总结”执行。工具可用且入口已确认时，实际调用前不完成交付待办。

创建后保留 `adminUrl` 和 `linkPresentation` 待办，继续搭建，到收尾再展示。`status=pending` 不代表已调用。应用壳、子技能直达、创建后的部分完成交付及缺少该字段的历史结果同样适用；不为展示重复创建资源。

云端优先 `show_link`，桌面端优先 `artifact_show_link`，否则使用当前可用的展示链接工具，参数以宿主声明为准。每轮最多调用一次，新一轮重新选择入口并调用。保留本轮所选 URL 对应的真实工具结果；创建/回读成功、Markdown 链接、侧边栏开页、`--no-open`、计划调用和上轮回执都不能替代。

只有工具清单明确无可用工具或实际调用失败时，才在内部记录依据并保留可点击链接，不重试业务写入、不把漏调解释成不可用。CLI 提供执行契约，调用由宿主 Agent 完成；请求被接受不证明卡片渲染或用户权限。

## 选择展示链接

- 本轮只成功修改一个已有页面，且没有其他资源或应用级修改：使用该页成功结果/回读的 `/workbench/{formUuid}`，优先 `workbenchUrl`；`formUrl` / `url` 路径匹配当前应用及页面时也可用。即使另有独立 custom 链接，本次仍选工作台。
- 其余情况使用 `create-app` / `app-list` 返回的当前应用 `adminUrl`：包括新建应用/页面、多页、其他资源/应用修改、没有页面修改，以及无法确认单页范围或工作台入口。
- 按本轮不同 `appType + formUuid` 计数，同页重复修改算一次，只读不计入修改。使用完整原始 URL；缺少入口时保留已有结果，不猜地址或额外写资源。用户明确排除的入口优先。

前台、业务后台、开发者后台及过程链接仍按原规则交付；这一次展示不替代其他必需入口。用户回复只讲业务结果、入口用途和必要动作，工具细节留在内部；用户明确询问时再说明。
