# 千问办公链接展示

当前宿主为千问办公（`runtime.tool=qwenwork`）时，每次向用户提供链接前都按本规则处理，覆盖进度、提问、操作提示和最终回复；不只适用于完整应用交付。其他宿主沿用自身展示能力。

## 选择真实工具

先核对当前会话直接声明的宿主工具及其参数。云端 UI MCP 的语义名称是 `show_link`（ui 服务），桌面端是 `artifact_show_link`；完整名称以当前工具清单为准，不能拼接 MCP 前缀或把其他服务的同名工具当成宿主工具。工具清单不可读或工具未声明时，按下文保留链接，不声称工具可用。

受支持的在线产物使用真实展示工具，每次只传一个参数：

```json
{"url":"本轮已确认的完整 HTTP(S) 业务地址"}
```

URL 取业务成功结果或针对性回读，保留原环境、查询参数和片段。名称、图标、资源类型和登记身份由宿主处理，不添加 `title`、`description`、`resourceType`、`auto_open` 或发布编号。CLI 原始 URL 字段保持不变；展示工具由 Agent 调用，不是 `openyida` 命令。

## 每个待展示链接的处理

1. 确认该链接确实需要交给用户，且属于本次成功完成、由用户要求交付的在线产物。完整应用沿用既有入口组和去重规则；单页、表单或配置任务只交付本轮所需入口，不因工具可用展开所有资源。
2. 当前两侧工具支持钉钉文档、AI 表格和宜搭应用在线产物。应用、前台、业务后台、开发者后台以及用户明确要求的表单/页面入口，均保留各自完整 URL，按宿主实际支持范围请求展示。不能只展示主入口、把其余入口当作已展示，也不能把表单地址换成应用根地址来取得卡片。
3. 在交付该链接的消息前调用宿主展示工具。同一轮同一完整 URL 已接受请求时复用，不因后续总结、卡片尚不可见或改用另一域名再次请求。
4. 工具成功只证明“展示请求已接受”。登记、权限和实际卡片渲染由宿主完成；没有后续证据时不宣称卡片已展示、链接权限已验证或页面验收通过。浏览器打开和创建命令 Hook 不能替代显式链接展示请求。
5. 不支持的链接、工具缺失、调用失败或宿主登记失败时，保留已完成业务和原始可点击链接，简短说明展示限制。不要重建资源、重复写入、改链接或循环请求来补卡片。

普通网页、读取/搜索引用、登录/权限申请/帮助入口、导出任务、临时下载地址和本地文件，不能冒充在线产物提交给当前这两个工具。需要用户操作的真实确认或权限入口按宿主支持的方式保留可点击链接，仍只说明业务动作和影响；本地交付文件使用真实文件展示工具。中间构建产物、CDN 地址、凭据和用户明确排除的资源继续保留在内部。当前工具不具备“任意链接都生成卡片”的能力。

## 完成前核对

核对本轮实际交付的每个入口：有已接受的展示请求，或有明确的展示受限记录及保留的原链接。展示失败不推翻已核实的业务成功，也不能被记成展示成功。最终总结保持简短，卡片的样式、布局和交互交给千问办公。
