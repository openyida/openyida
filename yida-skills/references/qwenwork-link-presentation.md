# 千问办公收尾链接展示

前台、业务后台、开发者管理后台的正常交付方式，以及对话中的宜搭操作和链接处理，都沿用原有规则。

每轮回复结束前，使用一次展示链接工具。本轮只修改一个已有页面时，展示该页面的 `/workbench/{formUuid}` 链接；其他情况展示当前应用的 `/admin` 开发者管理后台。

## 选择展示工具

千问办公云端优先使用 `show_link` 工具，桌面端优先使用 `artifact_show_link` 工具。首选工具不可用时，使用当前会话可用的展示链接工具。

## 选择展示链接

1. 按本轮实际成功修改的范围选择链接，不根据提到、读取或交付的链接数量判断。同一应用的同一页面多次修改仍算一个页面，只读取其他页面不计入修改。
2. 本轮仅修改一个已有页面，且没有其他资源或应用级修改时，使用该页面修改成功结果或回读中已确认的工作台链接。地址应为当前应用的 `/workbench/{formUuid}`，其中 `formUuid` 必须对应本轮修改的页面；即使该页另有独立访问链接，这次也使用工作台链接。
3. 新建应用或页面、修改多个页面、修改其他资源或应用设置、没有修改页面时，使用创建应用或查询应用结果中已确认的 `adminUrl`。无法确认单页修改范围或该页工作台链接时，也使用已确认的开发者后台链接。
4. 使用真实结果中的完整链接，不套用示例应用或页面，不自行猜测地址。没有已确认的可用链接时，保留本轮已完成的结果，不为展示链接额外创建或修改资源。用户明确排除的入口不展示。

## 展示与回复

先按原有方式处理本轮业务和所需链接，结束前只展示上面选中的一个链接。每轮最多调用一次，后续新一轮对话重新按本轮修改范围选择，不因为上轮已经展示过而省略。

工具不可用或展示失败时，保留选中入口的可点击链接，不反复调用或重新创建内容。

回复只说明本轮完成了什么、入口用于什么，以及用户需要做什么。工具名称、参数和后台处理过程不写进用户回复；用户明确询问技术细节时再按需说明。

这次展示不替代本轮原本需要交付的其他入口，也不代表已经验证用户的访问权限。
