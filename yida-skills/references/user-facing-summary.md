# 用户可见表达

适用于所有宿主中的创建、补齐、单页修复、美化、发布、升级、配置和数据任务。单点任务直接使用本规则，不必进入完整应用编排。

## 用户可见文案

页面文字、按钮和提示、需求与方案说明、提问与确认、任务标题、进度、错误提示、卡片、完成总结和后续建议，均使用业务语言。用实际业务名称、动作和结果说明谁要做什么、当前完成什么，以及需要处理的事项。

用户决定业务目标、规则和使用方式；实现方式由 Agent 按已确认范围处理。提问围绕业务选择，进度说明当前业务动作，问题说明实际影响和必要下一步，页面文案使用使用者熟悉的名称。必要的业务术语按当前场景解释。

命令、代码、协议、字段标识和诊断保留在 Agent 执行记录与机器回执中，并保持精确。用户明确需要命令、公式、代码或技术排障时，按所问范围提供必要技术内容，并结合业务操作解释；CLI 指令按明确的命令或用法请求提供。

以下示例按实际任务和已确认的结果使用：

| 场景 | 用户可见表达 |
| --- | --- |
| 核对表单信息 | 正在核对订单表单的信息。 |
| 检查页面 | 正在检查工作台页面。 |
| 登录需要恢复 | 请重新登录宜搭后继续。 |
| 保存结果待确认 | 订单是否保存成功待确认，我会先核对处理结果。 |
| 查询发布进度 | 页面待发布。 |

## 完成总结

默认用 1–3 句说明本轮改了什么和实际结果，简单修改一句即可。只有确实影响使用时才补充未完成项，需要用户操作时才说明必要下一步。按事实自然成句，省略固定的“改动 / 发布 / 环境说明”分段和逐项验证清单。入口按任务范围和对应技能的交付要求提供，用业务名称标注；宿主已展示同一入口时复用其交付机制。无需用户操作的成功结果直接收尾，不追加确认或刷新要求。

修复总结使用“已完成 ×× 问题的修复”，用一句话点明修复的问题及完成状态。多项修复合并概述；需要处理的剩余事项或用户操作，用一句话补充。

发布状态直接说明结果。CLI 指令仅用户明确询问命令或用法时提供；排障和实现细节只解释所问范围。

文件路径、内部 ID、校验字段、认证信息和环境排障经过留在执行记录。业务修复或发布请求本身不代表用户要看实现报告；技术问题只解释所问范围。验收按执行位置和对应技能进行，用户总结提炼业务结果，不贴回执原文；卡片与后续建议同样执行本规则。

未完成时说明功能影响与必要下一步。登录失效可说“页面暂未更新，请先重新登录宜搭”；组织或环境冲突先确认目标，不自行换环境。仅发布回读通过可说“页面已发布”，未验的功能不说成功，也不默认要求刷新或排障。

已核实相应结果时，可采用以下表达：

| 本轮结果 | 完成总结示例 |
| --- | --- |
| 单页问题已修复、发布并验证 | 已完成工作台待办区域不显示问题的修复。 |
| 修改并发布一处文案 | 已将工作台的“待清洁房间”改为“待清洁”，并更新页面。 |
| 修改完成，待发布 | 已完成文案修改，待发布。 |
| 登录失效，无法发布 | 页面暂未更新，请先重新登录宜搭。 |
| 发布完成，指定功能尚未验收 | 预约页面已发布，预约提交效果还未验证。 |

云端不执行浏览器验收，此项不当作交付失败或默认用户待办。不得表述“浏览器实机验收没做成”“沙箱装不上 Chromium”，也不默认要求用户打开、刷新或截图补验。仅用户明确要求页面验收或有具体业务问题时，说明该功能的未确认状态与必要操作。不得虚报视觉通过；权限范围、审批人选等真实业务缺项仍须说明。
