# 用户可见总结

适用于所有宿主中的创建、补齐、单页修复、美化、发布、升级、配置和数据任务，以及最终回复、交付卡片和后续建议。单点任务直接使用本规则，不必进入完整应用编排。

默认用 1–3 句说明本轮改了什么和实际结果，简单修改一句即可。只有确实影响使用时才补充未完成项，需要用户操作时才说明必要下一步。按事实自然成句，省略固定的“改动 / 发布 / 环境说明”分段和逐项验证清单。入口按任务范围和对应技能的交付要求提供，用业务名称标注；宿主已展示同一入口时复用其交付机制。无需用户操作的成功结果直接收尾，不追加确认或刷新要求。

修复总结使用“已完成 ×× 问题的修复”，用一句话点明修复的问题及完成状态。多项修复合并概述；需要处理的剩余事项或用户操作，用一句话补充。

发布命令、CLI 参数和操作步骤只在用户明确询问命令或用法时提供。用户询问发布状态时，直接说明是否完成；询问排障或实现细节时，只解释所问范围，不自动附上 CLI 指令。

文件名、路径、行号、内部 ID、JSON 字段、布尔值、字节数、错误码、Token/profile、域名切换和环境排障经过留在内部执行记录。用户明确询问技术细节时，只解释所问范围；业务修复或发布请求本身不代表用户要看实现报告。发布回读、健康检查和页面验收仍按各技能完成，结论由证据决定；无需把证据原文贴给用户。最终回复、卡片标题与描述、后续建议均按此规则检查，后续建议只写用户有必要进行的业务操作。

未完成时用一句话说明具体功能的影响和必要下一步。登录失效可说“页面暂未更新，请先重新登录宜搭”；目标组织或环境不一致时先确认正确目标，保持未完成状态，不自行改发到其他环境，也不将内部域名排查过程作为总结。仅完成发布回读时可说明“页面已发布”；需要报告尚未验收的功能时说“预约提交效果还未验证”，不把未验证写成成功，也不默认追加让用户刷新或排障的建议。

已核实相应结果时，可采用以下表达：

| 本轮结果 | 完成总结示例 |
| --- | --- |
| 单页问题已修复、发布并验证 | 已完成工作台待办区域不显示问题的修复。 |
| 修改并发布一处文案 | 已将工作台的“待清洁房间”改为“待清洁”，并更新页面。 |
| 修改已准备好，未完成发布 | 文案修改已准备好，尚未发布到页面。 |
| 登录失效，无法发布 | 页面暂未更新，请先重新登录宜搭。 |
| 发布完成，指定功能尚未验收 | 预约页面已发布，预约提交效果还未验证。 |

内部记录保存修改范围、发布回执、运行检查和必要诊断；用户总结依据这些记录提炼业务结果。发布成功只证明已发布，功能验证通过后才说功能已恢复；结果未知时先核实，无法核实时如实说明，不能用简短总结掩盖失败或扩大完成范围。
