# 用户可见表达

适用于所有宿主中的创建、补齐、单页修复、美化、发布、升级、配置和数据任务。单点任务直接使用本规则，不必进入完整应用编排。

## 用户可见文案

页面文字、按钮和提示、需求与方案说明、提问与确认、任务标题、进度、错误提示、卡片、完成总结和后续建议，均使用业务语言。用实际业务名称、动作和结果说明谁要做什么、当前完成什么，以及需要处理的事项。

用户决定业务目标、规则和使用方式；实现方式由 Agent 按已确认范围处理。提问围绕业务选择，进度说明当前业务动作，问题说明实际影响和必要下一步，页面文案使用使用者熟悉的名称。必要的业务术语按当前场景解释。

命令、代码、协议、字段标识和诊断保留在 Agent 执行记录与机器回执中，并保持精确。用户明确需要命令、公式、代码或技术排障时，按所问范围提供必要技术内容，并结合业务操作解释；CLI 指令按明确的命令或用法请求提供。

## 搭建任务的标题与提示

当前组织已核实后，搭建任务的可控标题和开始提示统一使用“在{组织名称}组织下搭建宜搭应用”，例如“在钉钉组织下搭建宜搭应用”。不要继续使用不带组织的“搭建宜搭应用”或“我来帮你搭建宜搭应用”。宿主提供会话标题更新能力时使用同一标题；未提供时只设置可控任务标题和正文，不声称已修改会话标题。

组织名称取当前宿主已确认的办公组织显示名，不使用环境标签、域名、组织 ID 或历史账号名称。显示名尚不可确认时使用“在当前组织下搭建宜搭应用”，不为标题查询历史凭据或打断必要的业务澄清。确认真实名称后更新可控标题；切换组织后重新核对，续做时不重复发送开始提示。标题与提示不追加登录或准备状态。

## 创建应用时的提示

真正开始创建新应用前，只告知一次：“当前在{组织名称}组织下为您创建{应用名称}应用”。组织名称取当前宿主已确认的办公组织显示名，应用名称取本次已确认的名称；这句话说明业务归属，不是登录或环境就绪提示。不得使用“宜搭 QwenWork 环境”等环境标签、域名、组织 ID 或历史账号名称替代组织名；当前显示名尚不可确认时使用“当前组织”，不编造名称。已有应用的续做、准备阶段和重试不重复发送，也不追加登录、换票或准备说明。

## 后台准备与受阻表达

所有宿主、所有阶段和失败恢复均静默处理安装、环境核验、登录、换票、Token 刷新、profile 选择和内部实现方案。开始、执行中、成功、失败、重试及总结均不播报这些过程；不使用“正在登录”“登录成功”“刷新 Token”“切换 profile”“先检查环境”等过渡句，也不把机器回执改写为聊天说明。耗时较长时只更新真实业务阶段，不用后台准备描述填充进度。

这是强制禁止项，覆盖回复正文、计划/待办、进度、卡片、工具调用的标题/说明及完成总结。禁止“环境就绪”“登录态就绪”“宜搭登录（桌面换票）”“登录态已就绪（当前组织：宜搭 QwenWork 环境）”及同义改写；也不要说“我会在后台准备”或“正在静默登录”。准备完成没有单独的用户消息，直接继续下一项业务操作。工具调用的原始命令和机器回执保留原样供执行判断，不能复制或改写成用户可见标题；可控标题使用当前真实业务阶段，不伪称业务操作已开始或完成。

需要用户操作时，直接说明最小动作及业务影响，不解释认证原因和修复方案。例如“请在打开的页面完成确认，完成后继续搭建”或“请先在千问办公切换到目标组织，再继续搭建”。仅使用命令或宿主实际返回的受支持入口；无有效入口时说明“当前暂时无法继续搭建，请稍后重试”，不要猜链接或要求用户提供凭据。真实权限不足仍需给出已返回的申请入口及所需业务权限。

此规则不省略用户必需的操作，也不允许后台无限恢复。按快照执行一次受支持流程，失败后保留已完成结果、停止依赖操作；内部保留完整结果与退出码。用户明确提出技术排障问题时只解释所问范围，原始凭据始终不可展示。

以下示例按实际任务和已确认的结果使用：

| 场景 | 用户可见表达 |
| --- | --- |
| 核对表单信息 | 正在核对订单表单的信息。 |
| 检查页面 | 正在检查工作台页面。 |
| 需要用户确认 | 请在打开的页面完成确认，完成后继续搭建。 |
| 保存结果待确认 | 订单是否保存成功待确认，我会先核对处理结果。 |
| 查询发布进度 | 页面待发布。 |

## 链接展示

千问办公中的宜搭应用或者宜搭相关的链接按[链接展示规则](qwenwork-link-presentation.md)使用展示链接工具。无法展示时，保留原来的可点击链接；需要说明时，只说“链接暂时无法展示，可点击此处打开”。回复只说明业务结果、链接用途和必要操作，不解释工具名称、参数或后台处理过程。不因总结简短而漏掉用户需要的入口，也不为补展示而重新创建内容。其他环境使用各自可用的展示方式。

## 完成总结

默认用 1–3 句说明本轮改了什么和实际结果，简单修改一句即可。只有确实影响使用时才补充未完成项，需要用户操作时才说明必要下一步。按事实自然成句，省略固定的“改动 / 发布 / 环境说明”分段和逐项验证清单。入口按任务范围和对应技能的交付要求提供，用业务名称标注；宿主已展示同一入口时复用其交付机制。无需用户操作的成功结果直接收尾，不追加确认或刷新要求。

修复总结使用“已完成 ×× 问题的修复”，用一句话点明修复的问题及完成状态。多项修复合并概述；需要处理的剩余事项或用户操作，用一句话补充。

发布状态直接说明结果。CLI 指令仅用户明确询问命令或用法时提供；排障和实现细节只解释所问范围。

文件路径、内部 ID、校验字段、认证信息和环境排障经过留在执行记录。业务修复或发布请求本身不代表用户要看实现报告；技术问题只解释所问范围。验收按执行位置和对应技能进行，用户总结提炼业务结果，不贴回执原文；卡片与后续建议同样执行本规则。

未完成时说明功能影响与必要下一步。需要用户确认可说“页面暂未更新，请在打开的页面完成确认”；组织冲突只引导通过宿主切换到用户指定的组织，不自行换环境。仅发布回读通过可说“页面已发布”，未验的功能不说成功，也不默认要求刷新或排障。

已核实相应结果时，可采用以下表达：

| 本轮结果 | 完成总结示例 |
| --- | --- |
| 单页问题已修复、发布并验证 | 已完成工作台待办区域不显示问题的修复。 |
| 修改并发布一处文案 | 已将工作台的“待清洁房间”改为“待清洁”，并更新页面。 |
| 修改完成，待发布 | 已完成文案修改，待发布。 |
| 需要用户确认，无法发布 | 页面暂未更新，请在打开的页面完成确认。 |
| 发布完成，指定功能尚未验收 | 预约页面已发布，预约提交效果还未验证。 |

云端按已完成的发布、配置和数据核对结果交付，页面未验状态留在内部。仅用户明确要求页面验收或存在影响使用的业务问题时，说明未确认的功能与必要操作；权限范围、审批人选等真实缺项照常说明。页面效果按实际证据表述，无需默认安排用户打开、刷新或截图补验。
