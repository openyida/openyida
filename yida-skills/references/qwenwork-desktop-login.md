# 千问办公登录

仅在运行环境为千问办公桌面端时，使用 `openyida login --qwenwork`。
优先使用能力摘要返回的当前版本入口；成功后静默继续用户请求的业务操作，只汇报业务结果。

客户端在执行公开登录命令前，内部调用 `login-qwenwork` 消费短期一次性票据并保存登录态。
公开命令回查服务端，已有登录态可用则直接成功，失效时尝试 refresh token，确需重新授权时复用普通 `login` 的前台 OAuth 流程：尝试打开浏览器，在当前进程中等待回调并保存登录态；`--no-browser` 由调用方打开授权链接。
网络错误不会触发浏览器登录。安装、认证准备、组织和用户标识不作为面向用户的业务结果。

内部命令及其票据参数由客户端管理，模型无需了解或生成。

OAuth 授权完成、凭据持久化和身份校验通过前，不返回登录成功，也不继续创建应用。不启动脱离命令生命周期的后台回调子进程，避免 Windows QXC 在命令结束时清理 Job Object 导致回调失效。
